P05 — Minimum Window Substring

Hard • LC #76 • Pattern: Have / Need with Frequency Map

📝 The Problem

Return the smallest substring of s that contains every character of t (counts matter). Empty string if impossible.

Example: s = "ADOBECODEBANC", t = "ABC" → "BANC"

📚 Jargon Buster

Need map
Required counts (built from t). Stays constant.
Window map
Counts of chars currently inside the window.
have / needCount
needCount = distinct chars t needs. have = how many of those are currently satisfied. Window valid iff have == needCount.
Multiplicities matter
If t = "AAB", you need at least 2 A's and 1 B inside the window.

🌟 In Layman's Terms

Grow the window until your "shopping list" is complete (have == needCount). Then shrink from the left while still complete — trying to find the smallest valid window. Repeat until end.

⚡ The Aha Moment

Window validity is captured by one integer (have). You don't need to compare maps each step — transitions (count just reached or just dropped below required) are the only events that move have.

🔧 Algorithm

  1. Build need from t. needCount = need.size(). have = 0.
  2. For each R: window[c]++. If window[c] reaches need[c]: have++.
  3. While have == needCount: record window if smaller. Then window[s[L]]--; if it dips below need: have--. L++.

☕ Java Solution

public String minWindow(String s, String t) {
    if (t.length() > s.length()) return "";
    Map<Character, Integer> need = new HashMap<>();
    for (char c : t.toCharArray()) need.merge(c, 1, Integer::sum);
    int needCount = need.size(), have = 0;
    Map<Character, Integer> window = new HashMap<>();
    int L = 0, bestLen = Integer.MAX_VALUE, bestStart = 0;
    for (int R = 0; R < s.length(); R++) {
        char c = s.charAt(R);
        window.merge(c, 1, Integer::sum);
        if (need.containsKey(c) && window.get(c).intValue() == need.get(c).intValue()) have++;
        while (have == needCount) {
            if (R - L + 1 < bestLen) { bestLen = R - L + 1; bestStart = L; }
            char lc = s.charAt(L);
            window.merge(lc, -1, Integer::sum);
            if (need.containsKey(lc) && window.get(lc) < need.get(lc)) have--;
            L++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
}

⏳ Complexity

Time
O(|s| + |t|)
Space
O(|alphabet|)

📈 Sliding Window Pattern

Have / Need: The canonical "contains all of T" pattern. Two counters (have, needCount) make validity checking O(1).
Key Insight: Maintaining boundary transitions of have is the trick that turns multiset-equality from O(alphabet) to O(1) per step.
