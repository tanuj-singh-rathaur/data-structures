P18 — Take K of Each Character From Left and Right

Medium • LC #2516 • Pattern: Longest Middle Window with Each Count ≤ total − K

📝 The Problem

Given s over alphabet {a, b, c} and integer k, take characters one at a time from either end. Return the minimum number of takes such that you have at least k of each character. -1 if impossible.

Example: s = "aabaaaacaabc", k = 2 → 8

📚 Jargon Buster

Complement reframe
Whatever you take from the ends, the middle is left behind. Minimum takes = n − (largest middle you can keep).
Middle validity
For each letter c: count_in_middle[c] ≤ total[c] − k. (You need k of each on the outside.)
Possible at all?
If any total[c] < k, return -1.

🌟 In Layman's Terms

The thing you remove from both ends is a contiguous middle you don't take. Find the largest middle you can leave, where outside still contains at least k of each. Answer = n − that length.

⚡ The Aha Moment

"Take from both ends" maps to "skip a middle." Solve the harder direction (smallest take) via the easier dual (largest legal middle).

🔧 Algorithm

  1. total = global count per letter. If any < k, return -1.
  2. Sliding window on s with constraint cnt[c] ≤ total[c] − k for every c.
  3. Track longest valid window L. Return n − L.

☕ Java Solution

public int takeCharacters(String s, int k) {
    int n = s.length();
    int[] total = new int[3];
    for (char c : s.toCharArray()) total[c - 'a']++;
    for (int v : total) if (v < k) return -1;
    int[] cap = { total[0] - k, total[1] - k, total[2] - k };
    int L = 0, best = 0;
    int[] cnt = new int[3];
    for (int R = 0; R < n; R++) {
        cnt[s.charAt(R) - 'a']++;
        while (cnt[0] > cap[0] || cnt[1] > cap[1] || cnt[2] > cap[2]) {
            cnt[s.charAt(L) - 'a']--;
            L++;
        }
        best = Math.max(best, R - L + 1);
    }
    return n - best;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Complement Window: Same reframe as "Min Operations to Reduce X to Zero" — minimize ends by maximizing middle. Standard sliding window template once reframed.
Key Insight: Two-ended removal problems almost always have a "leave the middle" reframing. The reframe converts them into one-piece sliding window problems.
