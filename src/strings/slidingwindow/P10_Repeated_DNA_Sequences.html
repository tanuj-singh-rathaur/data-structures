P10 — Repeated DNA Sequences

Medium • LC #187 • Pattern: Fixed Window of 10 + Two Sets

📝 The Problem

Return all 10-letter-long substrings that occur more than once in s.

Example: "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT" → ["AAAAACCCCC", "CCCCCAAAAA"]

📚 Jargon Buster

Seen / Result sets
Seen tracks substrings we've encountered once. Result holds substrings we've encountered ≥ 2 times. Splitting them avoids duplicates in the answer.
Fixed window of 10
Each step examines s.substring(R - 9, R + 1) — a constant-length slice.
Rolling hash (optional)
For huge inputs, encode each 10-mer as an integer (2 bits per base = 20 bits) and rolling-hash for O(1) updates per step. Not required for this problem size.

🌟 In Layman's Terms

Slide a 10-character viewing slot. Every time you see the same 10-character string twice, record it once in the result.

⚡ The Aha Moment

Two HashSets (seen, result) prevent duplicate output when a sequence appears 3+ times.

🔧 Algorithm

  1. seen = HashSet, result = HashSet.
  2. For each i = 0..n-10: sub = s.substring(i, i+10). If seen has it, add to result; else add to seen.
  3. Return list(result).

☕ Java Solution

public List<String> findRepeatedDnaSequences(String s) {
    Set<String> seen = new HashSet<>(), res = new HashSet<>();
    for (int i = 0; i + 10 <= s.length(); i++) {
        String sub = s.substring(i, i + 10);
        if (!seen.add(sub)) res.add(sub);
    }
    return new ArrayList<>(res);
}

⏳ Complexity

Time
O(n)
Space
O(n)

📈 Sliding Window Pattern

Fixed Window + HashSet: Trivial when window length is fixed: every substring is a candidate. Two sets keep the result unique even on triple-matches.
Key Insight: The clever pattern here is using !seen.add(sub) — the add returns false if it was already present, signaling "we have a duplicate."
