P03 — Range Sum Query - Immutable

Easy • LeetCode #303 • Pattern: Build the Prefix, Subtract

📝 The Problem

Design a class NumArray that supports sumRange(left, right) — returns the inclusive sum from index left to right. Many such calls may be made on the same array; the array does not change.

Example: nums=[−2,0,3,−5,2,−1]; sumRange(0,2)=1, sumRange(2,5)=−1, sumRange(0,5)=−3

📚 Jargon Buster

Immutable
The input never changes after construction. That's why a one-time pre-compute is perfect.
Inclusive range [l, r]
Both endpoints are included: indices l, l+1, ..., r.
1-indexed prefix array
We make P one longer than nums so P[0]=0 represents the empty prefix. This kills off-by-one bugs in the subtraction formula.

🌟 In Layman's Terms

Imagine a cash register tape. Each row shows the running total after that purchase. If a customer asks “what did we ring up between item 3 and item 7?” you subtract the running total at row 2 from the running total at row 7. One subtraction, no recounting.

⚡ The Aha Moment

If you pre-compute a prefix array P where P[i+1] = nums[0]+...+nums[i], then every range query collapses to a single subtraction: P[r+1] − P[l].

📺 Visual Walkthrough

Check: −2 + 0 + 3 = 1 ✓
Q2
sumRange(2, 5) = P[6] − P[2] = −3 − (−2) = −1
Check: 3 + (−5) + 2 + (−1) = −1 ✓
Q3
sumRange(0, 5) = P[6] − P[0] = −3 − 0 = −3
Whole array.

🔧 Algorithm

  1. In the constructor: build P of length n+1, with P[0]=0 and P[i+1]=P[i]+nums[i].
  2. For each sumRange(l, r): return P[r+1] − P[l].

☕ Java Solution

class NumArray {
    private final int[] P;
    public NumArray(int[] nums) {
        P = new int[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            P[i + 1] = P[i] + nums[i];
        }
    }
    public int sumRange(int left, int right) {
        return P[right + 1] - P[left];
    }
}

⏳ Complexity

Constructor
O(n)
Query
O(1)
Space
O(n)

📈 Prefix Sum Pattern

Build-the-Prefix, Subtract: The canonical use of prefix sums. Pay O(n) once, then every query is a single subtraction. The 1-indexed prefix style (P length n+1) is what makes the formula always work, even when l=0.
Key Insight: The prefix array length is n+1, not n. That extra slot at the front (P[0]=0) is what makes P[r+1] − P[l] work cleanly for any l, including l=0.
