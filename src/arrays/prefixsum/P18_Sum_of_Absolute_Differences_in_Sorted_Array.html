P18 — Sum of Absolute Differences in a Sorted Array

Medium • LC #1685 • Pattern: Split Contribution Left vs Right

📝 The Problem

Given a sorted array nums, return an array result where result[i] = sum of |nums[i] − nums[j]| for all j.

Example: nums = [2, 3, 5] → [4, 3, 5]

📚 Jargon Buster

Sorted invariant
Because the array is sorted, for any j < i: nums[j] ≤ nums[i], so |nums[i] − nums[j]| = nums[i] − nums[j]. Symmetric for j > i.
Left contribution
Sum over j < i of (nums[i] − nums[j]) = i · nums[i] − prefix[i].
Right contribution
Sum over j > i of (nums[j] − nums[i]) = (total − prefix[i+1]) − (n − i − 1) · nums[i].
Why prefix sums
They let us compute each side's contribution in O(1) per index.

🌟 In Layman's Terms

Because the array is sorted, everything to the left of i is ≤ nums[i], and everything to the right is ≥. So the absolute differences split cleanly into a left-sum and a right-sum — both expressible in terms of prefix sums.

⚡ The Aha Moment

Sorting kills the absolute value — you know the sign of every difference based on position. Then prefix sums make per-index O(1) lookups possible.

🔧 Algorithm

  1. Build prefix sums.
  2. For each i: left = i · nums[i] − P[i]; right = (P[n] − P[i+1]) − (n − i − 1) · nums[i].
  3. result[i] = left + right.

☕ Java Solution

public int[] getSumAbsoluteDifferences(int[] nums) {
    int n = nums.length;
    int[] P = new int[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    int[] res = new int[n];
    for (int i = 0; i < n; i++) {
        int left = i * nums[i] - P[i];
        int right = (P[n] - P[i + 1]) - (n - i - 1) * nums[i];
        res[i] = left + right;
    }
    return res;
}

⏳ Complexity

Time
O(n)
Space
O(n)

📈 Prefix Sum Pattern

Left/Right Split: Sortedness gives sign info; prefix sums give O(1) range totals. Together: per-index contribution in constant time.
Key Insight: Sorting + prefix sums = a powerful pair. Sort to remove the absolute value; prefix sums to compute split totals quickly.
