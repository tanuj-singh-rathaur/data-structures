P13 — Max Sum of Two Non-Overlapping Subarrays

Medium • LC #1031 • Pattern: Prefix Sums + Rolling Best

📝 The Problem

Given nums and two lengths L, M, find the maximum sum of two non-overlapping subarrays of lengths L and M (in either order).

Example: nums = [0,6,5,2,2,5,1,9,4], L=1, M=2 → 20

📚 Jargon Buster

Non-overlapping
The two subarrays share no index.
Two-pass split
For each i, track the best L-window ending at or before i (left side); pair it with the best M-window starting after i (right side). Symmetric for the other ordering.
Prefix sum lookup
Sum of a fixed-length window from prefix array in O(1): P[i+1] − P[i+1−len].

🌟 In Layman's Terms

At every index, ask: “What's the best L-sized window that ends at or before me, and what's the best M-sized window that starts after me?” Sum and track the max. Then swap L and M to handle the other ordering.

⚡ The Aha Moment

You don't need to try every (i, j) pair. Just sweep once tracking the best L-window seen so far, then sweep again with M-window. Combine.

🔧 Algorithm

  1. Build prefix sums.
  2. Helper best(L, M): scan i = M−1..n−1; track bestL (max L-window ending before this M-window); update answer with bestL + currentM.
  3. Return max(best(L, M), best(M, L)).

☕ Java Solution

public int maxSumTwoNoOverlap(int[] nums, int L, int M) {
    int n = nums.length;
    int[] P = new int[n + 1];
    for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
    return Math.max(best(P, n, L, M), best(P, n, M, L));
}
private int best(int[] P, int n, int L, int M) {
    int bestL = 0, ans = 0;
    for (int i = L + M; i <= n; i++) {
        bestL = Math.max(bestL, P[i - M] - P[i - M - L]);
        ans = Math.max(ans, bestL + (P[i] - P[i - M]));
    }
    return ans;
}

⏳ Complexity

Time
O(n)
Space
O(n)

📈 Prefix Sum Pattern

Prefix + Rolling Best: Pair a constant-time window sum (via prefix) with a rolling "best so far" of one window type to combine two windows in linear time.
Key Insight: When two windows must be combined, scan once with a rolling extreme of one and the current value of the other. The other ordering is just running the same loop with swapped arguments.
