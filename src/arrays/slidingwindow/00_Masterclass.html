💡 What Is Sliding Window? (Layman's Explanation)

Imagine looking through a letterbox at a long parade. You can only see a few floats at a time. As the parade moves, one new float enters the view from the right and one leaves from the left. You never have to look back — you just update your view incrementally.

That's the trick: instead of recomputing your “answer” for every possible subarray (O(n·k)), you let the answer slide with the window. Each step:

  1. Add the new element entering on the right.
  2. Remove the element leaving on the left (if the window has shifted).

One pass, O(n). The hard part is just deciding what to track inside the window.

📚 Jargon Buster (Confusing Terms Explained)

Window
A contiguous range [L, R] of the array (or string). The “window” is whatever's inside those two pointers.
Fixed-size window
The window's length stays constant (e.g., “size K”). Both pointers move together. Add right, remove left, repeat.
Variable-size / dynamic window
The window grows and shrinks based on a condition (e.g., “sum ≤ target”). Right pointer expands; left pointer contracts when the condition breaks.
Expand / Shrink
Expand = move right pointer further right (window grows). Shrink = move left pointer right (window gets smaller).
Invariant
A property the window must always maintain (e.g., “sum stays ≤ target,” or “at most K distinct characters”). When it breaks, you shrink until it holds again.
Frequency map / count map
A HashMap (or int array of 26 for lowercase letters) counting characters/values in the window. Constant-time updates as the window moves.
Have vs Need
Common in “Minimum Window Substring” style problems. Need = how many distinct chars the target requires. Have = how many of those are currently satisfied. Window is “valid” when have == need.
Deque (double-ended queue)
A queue you can push/pop from both ends. Used in “Sliding Window Maximum” to keep candidate maxes in monotonic order.
Monotonic deque
A deque whose stored values are kept in strictly decreasing (or increasing) order. Lets you grab the max (or min) of the current window in O(1).
Subarray vs Substring
“Subarray” for numbers, “substring” for strings. Both mean a contiguous slice — nothing skipped.

🔎 When Should You Use Sliding Window?

  • You need the longest, shortest, max, or min over all contiguous subarrays/substrings.
  • The window has a property that updates incrementally as elements enter/leave (sum, count, distinct, max).
  • Brute force is O(n²) or O(n·k) over all subarrays.
  • Words like “at most K”, “exactly K”, “sum ≥ target”, “contains all characters of”.
  • Crucially: moving the right pointer can only make things harder, never easier — that monotonicity is what lets you shrink the left without losing answers.

📈 The 4 Types of Sliding Window — Full Breakdown

① Fixed-Size Window

What it is: A window of exactly K elements. Slide it one step at a time, adding the new right element and removing the leaving left element. Track a running stat (sum, count, max).

Recognize it when:

  • The window size is given as a constant K
  • You're asked “max/min sum of subarray of size K”, “average of K consecutive”, etc.

The decision rule:

  • Build the first window of size K, capture its stat
  • For each subsequent position: stat += nums[R] − nums[R−K]
  • Update answer with current stat

Code Template: 
int sum = 0;
for (int i = 0; i < K; i++) sum += nums[i];
int best = sum;
for (int r = K; r < n; r++) {
    sum += nums[r] - nums[r - K];
    best = Math.max(best, sum);
}

② Variable Window (Grow + Shrink on Constraint)

What it is: Window expands as long as a condition holds (e.g., “sum ≤ K” or “at most one zero”). When the condition breaks, shrink from the left until it holds again. Update the answer at each valid state.

Recognize it when:

  • “Longest” or “shortest” subarray satisfying some constraint
  • All values are non-negative (otherwise sliding window's monotonicity breaks — use prefix sums)

The decision rule:

  • Move R right, update window state
  • While state violates the constraint: move L right, undo its contribution
  • Update answer with current window length

Code Template: 
int L = 0, sum = 0, best = Integer.MAX_VALUE;
for (int R = 0; R < n; R++) {
    sum += nums[R];
    while (sum >= target) {            // valid — try to shrink
        best = Math.min(best, R - L + 1);
        sum -= nums[L++];
    }
}

③ Window with Frequency Map (Char/Count Tracking)

What it is: Same expand/shrink pattern as Type 2, but the “state” is a frequency table of values in the window. You check the table to decide if the window is valid.

Recognize it when:

  • String problems with characters and counts
  • “Longest with at most K distinct”, “contains all of T”
  • Constraint involves multiplicities of items

The decision rule:

  • Use int[26] (lowercase) or HashMap for counts
  • On expand: increment count of new char
  • On shrink: decrement count of leaving char
  • Track a derived metric (max frequency, distinct count, “have” counter)
Worked Example: Longest Repeating Character Replacement — max window where at most K chars differ from the most frequent char.
s="AABABBA", K=1
R=0..3
window="AABA", freq={A:3, B:1}, maxFreq=3 windowLen=4, needToReplace = 4-3 = 1 ≤ K ✓
best = 4
R=4
window="AABAB", freq={A:3, B:2}, maxFreq=3 windowLen=5, needToReplace = 5-3 = 2 > K ✗
shrink: drop "A", L=1, freq={A:2,B:2}, maxFreq still tracked as 3 windowLen=4, OK ✓ (best stays 4)
R=5..6

Code Template: 
int[] count = new int[26];
int L = 0, maxFreq = 0, best = 0;
for (int R = 0; R < s.length(); R++) {
    count[s.charAt(R) - 'A']++;
    maxFreq = Math.max(maxFreq, count[s.charAt(R) - 'A']);
    while ((R - L + 1) - maxFreq > K) {
        count[s.charAt(L++) - 'A']--;
    }
    best = Math.max(best, R - L + 1);
}

④ Window with Monotonic Deque

What it is: You need max (or min) of the current window in O(1). A regular variable doesn't work because when the max leaves the window you'd need to recompute. A deque holding candidates in decreasing order solves it: the front is always the current max.

Recognize it when:

  • You need running max/min over every window
  • The window slides one step at a time

The decision rule (max version):

  • On expand: pop from the back while back < new element (those values can never be max again), then push new index
  • On shrink: if front index is out of window, pop front
  • Front of deque is the current window's max

Code Template: 
Deque<Integer> dq = new ArrayDeque<>();
int[] ans = new int[n - K + 1];
for (int i = 0; i < n; i++) {
    while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i]) dq.pollLast();
    dq.offerLast(i);
    if (dq.peekFirst() == i - K) dq.pollFirst();      // outside window
    if (i >= K - 1) ans[i - K + 1] = nums[dq.peekFirst()];
}

🔨 Universal Sliding Window Template

// Variable window (most common form)
int L = 0;
<state> window = init;
for (int R = 0; R < n; R++) {
    add nums[R] to window;
    while (window is INVALID) {
        remove nums[L] from window;
        L++;
    }
    // window [L..R] is valid — update answer
    best = best vs (R - L + 1) or sum or whatever;
}

🕑 Time Complexity

Brute force
O(n·k) or O(n²)
Sliding window
O(n)
Space
O(1) or O(k) for map/deque

Each element enters and leaves the window at most once. That's why even though there's a nested while, the total cost is still O(n).
