P08 — Sliding Window Maximum

Hard • LeetCode #239 • Pattern: Monotonic Deque

📝 The Problem

Given an array nums and a window size K, return an array containing the maximum value of each contiguous window of size K.

Example: nums = [1, 3, −1, −3, 5, 3, 6, 7], K = 3 → [3, 3, 5, 5, 6, 7]

📚 Jargon Buster

Deque (double-ended queue)
A queue that supports add/remove at both front and back in O(1). Java provides ArrayDeque.
Monotonic deque
A deque whose stored values stay in strictly decreasing (or increasing) order. For max-window we use decreasing — so the front is always the largest.
Storing indices, not values
We need to know when an element “ages out” (leaves the window). Storing its index lets us check that in O(1).
Why pop smaller from back
If a new element x arrives and the back of the deque is smaller than x, that old element can never be the max again as long as x is in the window. So pop it — it's permanently dominated.
Front = current max
By construction, after maintaining the invariant, the front of the deque holds the index of the current window's largest element.

🌟 In Layman's Terms

Imagine you're maintaining a leaderboard inside the window. When a new contender enters, anyone with a worse score who's also still in the window is now obsolete — they can never win as long as the better one is still there. Kick them out. Also, anyone at the front of the leaderboard who has aged out (left the window) must go. The front is always your current champion.

⚡ The Aha Moment

When a new value enters, every smaller value currently waiting in line is forever dominated. We can throw them away. The deque ends up holding only “potentially future winners” in strictly decreasing order — and the front of it is always the max.

🔧 Algorithm

  1. Use a deque storing indices.
  2. For each i in 0..n−1:
    • While deque non-empty and nums[deque.last()] < nums[i]: pop last.
    • Push i onto the back.
    • If deque.first() == i − K: pop front (out-of-window).
    • If i ≥ K − 1: record nums[deque.first()] in result.

☕ Java Solution

public int[] maxSlidingWindow(int[] nums, int K) {
    int n = nums.length;
    int[] ans = new int[n - K + 1];
    Deque<Integer> dq = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!dq.isEmpty() && nums[dq.peekLast()] < nums[i]) dq.pollLast();
        dq.offerLast(i);
        if (dq.peekFirst() == i - K) dq.pollFirst();
        if (i >= K - 1) ans[i - K + 1] = nums[dq.peekFirst()];
    }
    return ans;
}

⏳ Complexity

Time
O(n)
Space
O(K)

Each element is pushed and popped at most once → amortized O(1) per step.

📈 Sliding Window Pattern

Monotonic Deque: The standard pattern for “running max/min over a window.” The deque holds indices in monotonic order — smaller-and-older candidates are evicted because they can never beat the newcomer. Front is always the current best.
Key Insight: Once a value is dominated by a newer-and-bigger neighbor, it can never become the window max again. Drop it immediately. That insight is what turns the obvious O(n·K) into O(n).
