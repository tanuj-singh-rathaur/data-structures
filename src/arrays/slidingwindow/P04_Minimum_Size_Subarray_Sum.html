P04 — Minimum Size Subarray Sum

Medium • LeetCode #209 • Pattern: Variable Window (Shrink to Minimize)

📝 The Problem

Given positive integers nums and a target S, return the minimal length of a contiguous subarray whose sum is ≥ S. Return 0 if no such subarray exists.

Example: nums = [2, 3, 1, 2, 4, 3], S = 7 → 2 (from [4, 3])

📚 Jargon Buster

Minimal length
We want the shortest window that satisfies the condition (sum ≥ S), not the longest. Different goal → we shrink whenever the window is valid (to test if smaller still works).
Shrink-to-minimize
The opposite of P03. There we shrunk only when invalid; here we shrink while valid, recording each shrink-step's length, and stop only when the window becomes invalid.
Positive integers
All values > 0. Critical — sliding window correctness depends on it.

🌟 In Layman's Terms

Imagine pouring sand into a bucket until you've passed a weight threshold. Once you're at or past the threshold, start scooping sand off the bottom (left side) and check after each scoop — if you're still at threshold, the bucket is smaller, that's better. Stop scooping when you drop below; then keep pouring more.

⚡ The Aha Moment

Once the window's sum is ≥ S, every shorter sub-window from the same R could also be valid. Shrink L greedily; every time the sum is still ≥ S, record the new (smaller) length.

🔧 Algorithm

  1. Set L = 0, sum = 0, best = ∞.
  2. For each R: sum += nums[R].
  3. While sum ≥ S: best = min(best, R − L + 1); sum −= nums[L]; L++.
  4. Return best (or 0 if never updated).

☕ Java Solution

public int minSubArrayLen(int target, int[] nums) {
    int L = 0, sum = 0, best = Integer.MAX_VALUE;
    for (int R = 0; R < nums.length; R++) {
        sum += nums[R];
        while (sum >= target) {
            best = Math.min(best, R - L + 1);
            sum -= nums[L++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Shrink-to-Minimize: Whenever the window satisfies the goal, try shrinking from L — record each smaller-but-still-valid length. The opposite direction of “shrink-when-invalid” problems.
Key Insight: For “shortest valid” you shrink while valid. For “longest valid” you shrink while invalid. The condition flips but the skeleton is the same.
