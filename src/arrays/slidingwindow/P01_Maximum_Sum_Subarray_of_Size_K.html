P01 — Maximum Sum Subarray of Size K

Easy • LeetCode #2461 (similar) • Pattern: Fixed-Size Window

📝 The Problem

Given an array nums and an integer K, return the maximum sum of any contiguous subarray of length K.

Example: nums = [2, 1, 5, 1, 3, 2], K = 3 → 9 (from [5, 1, 3])

📚 Jargon Buster

Subarray of size K
K consecutive elements. So in an array of length n, there are n − K + 1 such subarrays.
Window sum
The running sum of the current K elements. When the window slides, we update it by adding the new right element and subtracting the leaving left element — no re-summing needed.
Brute force (recompute)
The naive way: for each starting index, loop K times to sum K elements. O(n·K). Sliding window kills the inner loop.

🌟 In Layman's Terms

Stand at the start with a viewing slot exactly K wide. Add up what you see. Now slide the slot one step right: the value entering on the right joins your sum; the value leaving on the left subtracts out. Same window, new sum, in O(1).

⚡ The Aha Moment

You're not recomputing the sum — you're updating it. Each slide is two operations (one add, one subtract), no matter how big K gets.

🔧 Algorithm

  1. Compute the sum of the first K elements; call it best.
  2. For R from K to n−1: sum += nums[R] − nums[R−K].
  3. Update best = max(best, sum).
  4. Return best.

☕ Java Solution

public int maxSumSubarray(int[] nums, int K) {
    int sum = 0;
    for (int i = 0; i < K; i++) sum += nums[i];
    int best = sum;
    for (int r = K; r < nums.length; r++) {
        sum += nums[r] - nums[r - K];
        best = Math.max(best, sum);
    }
    return best;
}

📈 Sliding Window Pattern

Fixed-Size Window: The textbook intro to sliding window. Build first window, then slide one step at a time with one add and one subtract. Used for problems with a fixed K.
Key Insight: Adjacent windows overlap by K−1 elements. There's no need to throw that work away — reuse it.
