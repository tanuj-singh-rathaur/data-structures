P06 — Longest Repeating Character Replacement

Medium • LeetCode #424 • Pattern: Window + Frequency Map

📝 The Problem

Given a string s (uppercase letters only) and an integer K, you may replace up to K characters with any letter. Return the length of the longest substring containing the same letter after replacements.

Example: s = "AABABBA", K = 1 → 4 (replace one B in "AABA" or "ABBA")

📚 Jargon Buster

Frequency map (int[26])
An array indexed by letter where count[c] = how many times c appears in the current window. For uppercase letters use 26 slots.
maxFreq
The highest count any letter has reached in the window. The number of characters we'd need to replace = windowSize − maxFreq.
Why we never decrement maxFreq
It's a clever trick. If maxFreq stays artificially high after shrinking, the window won't grow until a real new maxFreq beats it. That's actually fine because the answer never decreases — we only care about windows that exceed the current best.
Replacement count
windowLength − maxFreq — how many letters in the window are not the dominant one. Window valid ↔ this ≤ K.

🌟 In Layman's Terms

You're picking a window of letters. Keep track of which letter shows up most often inside; everyone else needs to be replaced. If “everyone else” is more than K, the window is too greedy — shrink from the left. The goal: max out the window size while keeping “non-majority count” ≤ K.

⚡ The Aha Moment

You don't need to recompute maxFreq when shrinking. The answer can only grow when a new larger maxFreq appears — so a stale (but never-too-small) maxFreq is harmless. This keeps the loop O(n) instead of O(26·n).

🔧 Algorithm

  1. Maintain count[26], pointers L=0, and maxFreq=0.
  2. For each R: increment count[s[R]]; update maxFreq.
  3. If (R − L + 1) − maxFreq > K: decrement count[s[L]] and L++.
  4. Update best = max(best, R − L + 1).

☕ Java Solution

public int characterReplacement(String s, int K) {
    int[] count = new int[26];
    int L = 0, maxFreq = 0, best = 0;
    for (int R = 0; R < s.length(); R++) {
        count[s.charAt(R) - 'A']++;
        maxFreq = Math.max(maxFreq, count[s.charAt(R) - 'A']);
        if ((R - L + 1) - maxFreq > K) {
            count[s.charAt(L) - 'A']--;
            L++;
        }
        best = Math.max(best, R - L + 1);
    }
    return best;
}

Time
O(n)
Space
O(26) = O(1)

📈 Sliding Window Pattern

Frequency Map Window: The window tracks per-character counts. Validity is derived from those counts via length − maxFreq ≤ K. Notice we use if, not while — the window length never shrinks past the previous best, so a single shift is enough.
Key Insight: The clever optimization — not decrementing maxFreq on shrink — only works because we're tracking the maximum answer, not the current truth. A “stale optimistic” maxFreq is harmless for that goal.
