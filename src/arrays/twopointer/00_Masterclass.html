💡 What Is Two Pointer? (Layman's Explanation)

Imagine you're in a sorted lineup of people by height and you want to find two people whose combined height is exactly 180 cm. The dumb way is to pair everyone with everyone else — that's O(n²). The smart way:

  1. Put your left hand on the shortest person (far left).
  2. Put your right hand on the tallest person (far right).
  3. Check their sum:
      • Too tall? Move your right hand left (we need someone shorter).
      • Too short? Move your left hand right (we need someone taller).
      • Exact match? Done!

Each step eliminates an entire row of possibilities. That's why it's O(n) instead of O(n²). The secret weapon: the array is sorted, so moving a pointer in one direction always makes the sum go in a predictable direction.

🔎 When Should You Use Two Pointer?

Look for these signals in the problem:

  • The array is sorted (or you can sort it).
  • You're looking for a pair/triplet/k-tuple that meets some condition.
  • The problem says O(1) extra space.
  • You need to remove elements in-place.
  • You need to check/reverse from both ends (palindrome, reverse).
  • The brute force is O(n²) and you know there must be a better way.

📈 The 5 Types of Two Pointer — Full Breakdown

① Opposite Ends  (Converging)

What it is: One pointer starts at the left end, one at the right end. They march toward each other. Each step you look at both values and decide which side to move — you never move both at once (unless you found the answer).

Recognize it when:

  • The array is sorted (or you can sort it)
  • You need a pair whose sum / product / area satisfies a condition
  • You're checking symmetry from both ends (palindrome, reverse)
  • Brute force would be O(n²) and O(1) space is required

The decision rule:

  • Result too big → move R left (shrink from the right)
  • Result too small → move L right (grow from the left)
  • Exact match → record answer, move both
Worked Example: Two Sum II — find pair summing to 9 in [2, 7, 11, 15]
Step-by-step trace  —  blue cell = L  |  red cell = R
Start
[2L7 11 15R]
L=0 (value 2), R=3 (value 15)
Step 1
[2L7 11 15R]
sum = 2 + 15 = 17 > 9 → too big → R-- (move R left)
Step 2
[2L7 11R15 ]
sum = 2 + 11 = 13 > 9 → too big → R-- (move R left)
Step 3
[2L7R11 15 ]
sum = 2 + 7 = 9 = 9 → FOUND! return [1, 2]
Code Template: 
int left = 0, right = n - 1;
while (left < right) {
    int val = compute(arr[left], arr[right]);
    if      (val == target) { /* found */ break; }
    else if (val < target)  left++;    // need bigger
    else                    right--;   // need smaller
}

② Slow + Fast  (Same Direction)

What it is: Both pointers move left to right, but at different speeds. Fast is the reader — it visits every element without exception. Slow is the writer — it only advances when fast finds something worth keeping. Everything before slow at the end is your answer.

Recognize it when:

  • Remove / filter elements in-place without extra space
  • "Move all X to the end" or "keep only Y"
  • You need to compact an array (skip zeroes, skip duplicates, skip a value)

The decision rule:

  • fast always advances every iteration
  • slow only advances when nums[fast] is a “good” element
  • Write nums[fast] into nums[slow] before advancing slow
Worked Example: Move Zeroes — move all zeros to the end in [0, 1, 0, 3, 12]
Step-by-step trace  —  green cell = S (write head)  |  orange cell = F (scanner)
Start
[0S/F1 0 3 12 ]
S=0, F=0 — both start at index 0
Step 1
[0F1 0 3 12 ]
    S is also at index 0 (not moving)
nums[F] = 0 → BAD (zero) F++ only — S stays put
Step 2
[1S1F0 3 12 ]
nums[F] = 1 → GOOD write nums[S] = 1, then S++, F++ (array[0] is now 1)
Step 3
[1 1S0F3 12 ]
nums[F] = 0 → BAD (zero) F++ only — S stays put
Step 4
[1 3S0 3F12 ]
nums[F] = 3 → GOOD write nums[S] = 3, then S++, F++

Code Template: 
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (nums[fast] /* is "good" */) {
        nums[slow++] = nums[fast];
    }
}
// slow = count of good elements

③ Fix One + Two Pointer  (k-Sum Family)

What it is: You lock one element with an outer loop (i), then run a Type 1 (Opposite Ends) two-pointer on the subarray to the right. This turns a 3-variable problem into a 2-variable one you already know how to solve. 4Sum adds one more fixed loop.

Recognize it when:

  • Find all triplets / quadruplets summing to a target
  • Brute force is O(n³) and you suspect O(n²) exists
  • Duplicates must be avoided in the result

The decision rule (inner two-pointer):

  • sum < target → L++  (need bigger left value)
  • sum > target → R--  (need smaller right value)
  • sum == 0 → record, skip duplicate L and R values, then L++ R--
  • After inner loop, skip duplicate i values before next outer iteration

Code Template: 
Arrays.sort(nums);
for (int i = 0; i < n - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue;  // skip dup i
    int left = i + 1, right = n - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if      (sum == target) { /* save, skip dupes, L++, R-- */ }
        else if (sum < target)  left++;
        else                    right--;
    }
}

④ Fill From Back  (Reverse Fill)

What it is: You fill a result array from right to left (largest value first). Two pointers sit at the two ends of the source data, and you always write the bigger of the two into the next available slot from the right. This avoids overwriting data you still need.

Recognize it when:

  • You need to merge or transform a sorted array, and writing from the front would overwrite values you still need
  • The largest values come from the two ends (e.g., negatives squared become large positives)
  • There is pre-allocated tail space (e.g., Merge Sorted Array)

The decision rule:

  • Compare absolute value (or actual value) at L vs R
  • Write the larger into result[pos--]
  • Advance the pointer whose value was just written
Worked Example: Squares of a Sorted Array — square [-4, -1, 0, 3, 10] in sorted order
Step-by-step trace  —  blue = L  |  red = R  |  green = written to result
Start
source array:
[-4L-1 0 3 10R]
result (pos=4):
[_ _ _ _ _ ]
|L| = |-4| = 4 |R| = |10| = 10
Step 1
[-4L-1 0 3 10R]
[_ _ _ _ 100 ]
|R|=10 > |L|=4 → write 10²=100 at result[4] R-- (pos=3)
Step 2
[-4L-1 0 3R10 ]
[_ _ _ 16 100 ]
|L|=4 > |R|=3 → write (-4)²=16 at result[3] L++ (pos=2)
Step 3
[-4 -1L0 3R10 ]
[_ _ 9 16 100 ]
|R|=3 > |L|=1 → write 3²=9 at result[2] R-- (pos=1)
Step 4
[-4 -1L0R3 10 ]
[_ 1 9 16 100 ]
|L|=1 > |R|=0 → write (-1)²=1 at result[1] L++ (pos=0)

[-4 -1 0L=R3 10 ]
[0 1 9 16 100 ]
L == R → write 0²=0 at result[0] Loop ends. Done!
Code Template: 
int left = 0, right = n - 1, pos = n - 1;
int[] result = new int[n];
while (left <= right) {
    int lVal = Math.abs(nums[left]);
    int rVal = Math.abs(nums[right]);
    if (lVal > rVal) { result[pos--] = lVal * lVal; left++;  }
    else             { result[pos--] = rVal * rVal; right--; }
}

⑤ Three Pointer  (Partition)

What it is: Three boundaries divide the array into four zones: processed-left, unknown-middle, processed-right. The low pointer is the right edge of the "left zone". The mid pointer is the scanner. The high pointer is the left edge of the "right zone". The middle shrinks until mid passes high.

Recognize it when:

  • Three-category partition in a single pass (classic Dutch National Flag)
  • Two pointers are not enough because there are three distinct groups

The decision rule (for 0/1/2 sort):

  • nums[mid] == 0 → swap(mid, low), low++, mid++
  • nums[mid] == 1 → mid++ only (already in place)
  • nums[mid] == 2 → swap(mid, high), high--  but do NOT mid++ (swapped value is unknown!)
Worked Example: Sort Colors — sort [2, 0, 2, 1, 1, 0] in one pass

Step 3
[0 0S/F2 1 1H2 ]
mid=1, nums[mid]=0 → swap(mid, low) low++ (low=2), mid++ (mid=2)
Step 4
[0 0 2S/F1 1H2 ]
mid=2, nums[mid]=2 → swap(mid, high) array: [0,0,1,1,2,2] high-- (high=3) mid stays at 2 (don't advance!)

[0 0 1S/F1H2 2 ]
mid=2, nums[mid]=1 → mid++ only (1 is already in the correct middle zone)
Step 6
[0 0 1S1F/H2 2 ]
mid=3, nums[mid]=1 → mid++ only

[0 0 1 1 2 2 ]
mid=4 > high=3 → loop ends Result: [0, 0, 1, 1, 2, 2]
Code Template: 
int low = 0, mid = 0, high = n - 1;
while (mid <= high) {
    if      (nums[mid] == 0) swap(nums, low++, mid++);  // send to left zone
    else if (nums[mid] == 1) mid++;                     // already in middle
    else                     swap(nums, mid, high--);   // send to right zone
    // NOTE: do NOT mid++ after swapping a 2 — the new nums[mid] is unknown
}
