P19 — Best Time to Buy and Sell Stock with Transaction Fee

Medium • LC #714 • Pattern: Two-State Rolling DP

📝 The Problem

Multiple buy/sell, but each completed transaction costs fee. Return max profit.

Example: prices = [1,3,2,8,4,9], fee = 2 → 8

📚 Jargon Buster

Two states
cash: no share; hold: own a share.
Transitions
cash' = max(cash, hold + price − fee), hold' = max(hold, cash − price).
Where does the fee go
Subtract it on the sell transition. (Could also charge on buy; same total — just a convention.)

🌟 In Layman's Terms

Two buckets: cash (no share) and hold (have a share). Each day you can stay put or transition. Selling moves money from hold to cash minus the fee. Track both buckets; final answer = cash.

⚡ The Aha Moment

The fee makes greedy “buy low / sell high” a bit subtler — small profits may not cover the fee. The two-state DP handles this naturally by always taking the max.

🔧 Algorithm

  1. Initialize cash = 0, hold = −prices[0].
  2. For each next price: cash = max(cash, hold + price − fee); hold = max(hold, cash − price). (Order matters; use saved cash.)
  3. Return cash.

☕ Java Solution

public int maxProfit(int[] prices, int fee) {
    int cash = 0, hold = -prices[0];
    for (int i = 1; i < prices.length; i++) {
        int prevCash = cash;
        cash = Math.max(cash, hold + prices[i] - fee);
        hold = Math.max(hold, prevCash - prices[i]);
    }
    return cash;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Kadane Pattern

Two-State DP: Cash and hold trading off, with a fee on the sell transition. Same skeleton as the cooldown problem (P18) minus the third state.
Key Insight: Use prevCash when updating hold, because both states update from prior step's values — if you don't, you'd use the just-updated cash and double-count.
