P18 — Best Time to Buy and Sell Stock with Cooldown

Medium • LC #309 • Pattern: Three-State Rolling DP

📝 The Problem

Multiple buy/sell transactions, but after selling you must rest one day before buying again. Return max profit.

Example: prices = [1, 2, 3, 0, 2] → 3

📚 Jargon Buster

Three states
hold: own a share. sold: just sold today (cooldown begins). rest: no share, no fresh sale — eligible to buy.
Cooldown encoding
The "sold" state is what enforces the cooldown: from "sold" you can only go to "rest" (not directly back to "hold").
Transitions
hold' = max(hold, rest − price), sold' = hold + price, rest' = max(rest, sold).

🌟 In Layman's Terms

Three buckets of money — one for “I currently own,” one for “I just sold,” one for “I'm resting.” Each day, money moves between buckets according to the allowed transitions. The final answer is the larger of “sold” and “rest”.

⚡ The Aha Moment

The cooldown is naturally captured by a third state. The DAG of states is: rest → hold → sold → rest. Three scalars and three transitions encode the whole policy.

🔧 Algorithm

  1. Initialize hold = −prices[0], sold = 0, rest = 0.
  2. For each price: update all three together (use saved previous values).
  3. Return max(sold, rest).

☕ Java Solution

public int maxProfit(int[] prices) {
    int hold = -prices[0], sold = 0, rest = 0;
    for (int i = 1; i < prices.length; i++) {
        int prevHold = hold, prevSold = sold, prevRest = rest;
        hold = Math.max(prevHold, prevRest - prices[i]);
        sold = prevHold + prices[i];
        rest = Math.max(prevRest, prevSold);
    }
    return Math.max(sold, rest);
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Kadane Pattern

Three-State DP: When the rule introduces a "you just did X" condition, add a state for it. Same family as the two-state stock problems but with an extra cooldown node.
Key Insight: Cooldown isn't a "skip n days" loop — it's a third DP state. The state machine encodes the constraint, and the recurrence stays simple and constant-space.
