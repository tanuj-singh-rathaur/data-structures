P05 — Group Anagrams

Medium • LC #49 • Pattern: Canonical Key → Group

📝 The Problem

Group strings that are anagrams of each other.

📚 Jargon Buster

Canonical Key
A unique fingerprint shared by all members of an equivalence class. For anagrams: sorted string or 26-length count.
Equivalence Class
Items considered "the same" under some relation (anagram, isomorphism, etc.).

🌟 In Layman's Terms

Two strings are anagrams iff their sorted versions are identical. Use that sorted version as a map key; values are the list of strings sharing it.

⚡ The Aha Moment

Replace "compare all pairs" with "give each item a label, group by label."

🔧 Algorithm

  1. map<String, List<String>>.
  2. For each s: key = sorted(s); map.computeIfAbsent(key, _ -> new ArrayList<>()).add(s).
  3. Return new ArrayList<>(map.values()).

☕ Java Solution

public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();
    for (String s : strs) {
        char[] c = s.toCharArray();
        Arrays.sort(c);
        map.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}

⏳ Complexity

Time
O(n · k log k)
Space
O(n · k)

k = max string length. Using 26-int count as key gives O(n · k).

📈 Frequency Pattern

Signature-Key Grouping: Whenever items are "equivalent under permutation/transform," map them to a canonical form and group.
Key Insight: Hashing on a canonical signature replaces O(n²) pairwise comparison with O(n) bucketing.
