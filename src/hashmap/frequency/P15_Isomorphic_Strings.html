P15 — Isomorphic Strings

Easy • LC #205 • Pattern: Two HashMaps (s↔t bijection)

📝 The Problem

Strings s and t are isomorphic iff chars can be replaced via a 1-to-1 mapping s → t (no two chars map to the same).

📚 Jargon Buster

Bijection
1-to-1 mapping both ways. Need s→t AND t→s consistent.

🌟 In Layman's Terms

Walk both strings together. If you've seen s[i] before, it must map to the same t[i] as before. Same in reverse.

⚡ The Aha Moment

One map only isn't enough: "abc" → "aaa" passes left-to-right but fails right-to-left.

🔧 Algorithm

  1. Two int[128] arrays mapST, mapTS, initialised to 0.
  2. For i: cs = s[i], ct = t[i]. If mapST[cs] == 0 && mapTS[ct] == 0 ⇒ set both. Else if mismatch ⇒ false.

☕ Java Solution

public boolean isIsomorphic(String s, String t) {
    int[] mST = new int[128], mTS = new int[128];
    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i), b = t.charAt(i);
        if (mST[a] == 0 && mTS[b] == 0) { mST[a] = b; mTS[b] = a; }
        else if (mST[a] != b || mTS[b] != a) return false;
    }
    return true;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Frequency Pattern

Two-Way Mapping: For bijection checks, you need both directions — one direction is half the constraint.
Key Insight: Using char value as array index (size 128) makes the "0 means unset" sentinel work without HashMap overhead.
