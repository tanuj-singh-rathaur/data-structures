P01 — Koko Eating Bananas

Medium • LC #875 • Pattern: BS smallest rate k · predicate sum(ceil(piles/k)) ≤ h

📝 The Problem

Koko has piles of bananas and h hours. Eating at speed k bananas/hour, she finishes pile i in ceil(piles[i] / k) hours. Min k such that total hours ≤ h.

📚 Jargon Buster

Eating Speed (k)
Bananas per hour. Bigger ⇒ faster ⇒ feasible. Smaller ⇒ slower ⇒ may exceed h.
Monotone Predicate
If k works (hours ≤ h), every k' > k also works ⇒ classic feasibility region for BS.
Ceiling
(p + k − 1) / k using integer math.

🌟 In Layman's Terms

Guess Koko's eating speed. If she finishes in time, try slower. Else try faster. Binary search the speed.

⚡ The Aha Moment

The answer is not in the input — it's in the abstract range [1, max(piles)]. Binary-searching this range with a feasibility check is far faster than trying every k.

🔧 Algorithm

  1. lo = 1, hi = max(piles).
  2. While lo < hi: mid; total = Σ ceil(piles[i]/mid).
  3. If total ≤ h: hi = mid. Else lo = mid + 1.
  4. Return lo.

☕ Java Solution

public int minEatingSpeed(int[] piles, int h) {
    int lo = 1, hi = 0;
    for (int p : piles) hi = Math.max(hi, p);
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        long hours = 0;
        for (int p : piles) hours += (p + mid - 1) / mid;
        if (hours <= h) hi = mid;
        else            lo = mid + 1;
    }
    return lo;
}

⏳ Complexity

Time
O(n log max(piles))
Space
O(1)

📈 BS-on-Answers Pattern

Minimize Rate: The skeleton "BS rate + sum(ceil/floor)" applies to many "min capacity/divisor/speed" problems.
Key Insight: Whenever the answer is a parameter you "tune" and feasibility is monotone, binary search beats linear scan.
