P19 — Maximum Count of Positive Integer and Negative Integer

Easy • LC #2529 • Pattern: Two Boundary Searches

📝 The Problem

Sorted array nums. Let pos = number of positives, neg = number of negatives. Return max(pos, neg).

Example: [-2, -1, -1, 1, 2, 3] → 3

📚 Jargon Buster

Count via boundaries
neg = lower_bound(0) (first index ≥ 0). pos = n − upper_bound(0) (count of strictly greater than 0).
Zero handling
Zero is neither positive nor negative; the two boundary indices correctly skip zeros.

🌟 In Layman's Terms

Find where 0 would slot in (number of negatives), and where the first strictly positive value is (positives = n − that index). Return the larger.

⚡ The Aha Moment

Both counts come from two boundary searches. No iteration needed; pure log-n.

🔧 Algorithm

  1. negCount = lower_bound(nums, 0).
  2. posCount = n − upper_bound(nums, 0).
  3. Return max(negCount, posCount).

☕ Java Solution

public int maximumCount(int[] nums) {
    int n = nums.length;
    int neg = lowerBound(nums, 0);
    int pos = n - upperBound(nums, 0);
    return Math.max(neg, pos);
}
private int lowerBound(int[] a, int t) {
    int L = 0, R = a.length;
    while (L < R) {
        int mid = L + (R - L) / 2;
        if (a[mid] >= t) R = mid;
        else             L = mid + 1;
    }
    return L;
}
private int upperBound(int[] a, int t) {
    int L = 0, R = a.length;
    while (L < R) {
        int mid = L + (R - L) / 2;
        if (a[mid] > t) R = mid;
        else            L = mid + 1;
    }
    return L;
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 Binary Search Pattern

Two Boundary Searches: Lower + Upper bound is the universal "count occurrences" trick. The difference between them equals the count of equal elements; complementary indices give the strictly-less-than / strictly-greater-than counts.
Key Insight: Once you've internalized lower-bound and upper-bound, any "count of X in sorted array" reduces to two log-n calls.
