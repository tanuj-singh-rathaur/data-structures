P20 — Successful Pairs of Spells and Potions

Medium • LC #2300 • Pattern: Sort + Per-Query Lower Bound

📝 The Problem

For each spell s, count potions p where s * p ≥ success.

Example: spells = [5,1,3], potions = [1,2,3,4,5], success = 7 → [4, 0, 3]

📚 Jargon Buster

Per-query lower bound
Sort potions. For each spell s, the threshold potion is ⌈success / s⌉. Lower bound of that threshold gives the first qualifying potion; count = n − that index.
Long arithmetic
success can be up to 10^10; use long for the threshold and comparisons.
Ceiling division
⌈success / s⌉ = (success + s − 1) / s (integer math).

🌟 In Layman's Terms

Sort potions once. For each spell, work out the minimum potion strength required. Binary search how many potions clear that bar.

⚡ The Aha Moment

The threshold depends on the spell but the sorted potion list is shared — reuse it across all queries.

🔧 Algorithm

  1. Sort potions.
  2. For each spell: threshold = ceil(success / spell). lower = lowerBound(potions, threshold). result = n − lower.

☕ Java Solution

public int[] successfulPairs(int[] spells, int[] potions, long success) {
    java.util.Arrays.sort(potions);
    int n = potions.length;
    int[] res = new int[spells.length];
    for (int i = 0; i < spells.length; i++) {
        long need = (success + spells[i] - 1) / spells[i];
        int L = 0, R = n;
        while (L < R) {
            int mid = L + (R - L) / 2;
            if (potions[mid] >= need) R = mid;
            else                      L = mid + 1;
        }
        res[i] = n - L;
    }
    return res;
}

⏳ Complexity

Time
O((s + n) log n)
Space
O(1)

s = # spells, n = # potions.

📈 Binary Search Pattern

Sort + Per-Query Lower Bound: Pre-sort the lookup table once; answer each query in O(log n) via lower bound. The classic pattern for offline range-count queries.
Key Insight: Watch the overflow: multiplying spell × potion can overflow int. Either cast to long or compute the threshold and search instead — the latter is cleaner.
