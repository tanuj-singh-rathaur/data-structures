P08 — Single Element in a Sorted Array

Medium • LC #540 • Pattern: Index Parity Invariant

📝 The Problem

Sorted array where every element appears exactly twice except one. Find the unique element in O(log n).

Example: [1, 1, 2, 3, 3, 4, 4, 8, 8] → 2

📚 Jargon Buster

Index parity
Before the unique element, pairs occupy (even, odd) indices: arr[2k] == arr[2k+1]. After it, pairs are at (odd, even): arr[2k+1] == arr[2k+2]. The "switch" happens at the unique element.
Even mid trick
Force mid to be even via mid &= ~1. Then check arr[mid] == arr[mid+1] to decide direction.

🌟 In Layman's Terms

Pairs occupy (even, odd) index positions before the unique element. So if you force mid to be even and check whether arr[mid] == arr[mid+1], you can tell whether the unique element is to the left or right.

⚡ The Aha Moment

You don't need to count or hash anything — the index parity of pairs encodes the location of the unique element. Binary search the boundary.

🔧 Algorithm

  1. L = 0, R = n − 1.
  2. While L < R: mid = L + (R−L)/2; if mid odd, mid--.
  3. If arr[mid] == arr[mid+1]: unique is to the right → L = mid + 2.
  4. Else: unique is at mid or to the left → R = mid.
  5. Return arr[L].

☕ Java Solution

public int singleNonDuplicate(int[] nums) {
    int L = 0, R = nums.length - 1;
    while (L < R) {
        int mid = L + (R - L) / 2;
        if ((mid & 1) == 1) mid--;
        if (nums[mid] == nums[mid + 1]) L = mid + 2;
        else                            R = mid;
    }
    return nums[L];
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 Binary Search Pattern

Index Parity Invariant: A clever monotonic predicate — "the pair starting at mid is still aligned to even indices." Boundary search via the same lower-bound template.
Key Insight: Forcing mid to be even keeps the parity invariant clean and lets you compare arr[mid] == arr[mid+1] safely.
