💡 What Is Binary Search? (Layman's Explanation)

You're guessing a number between 1 and 100. Instead of trying 1, 2, 3, …, you guess 50. Too high? Now you know it's in 1–49 and you guess 25. Too low? It's in 26–49 and you guess 37. Each guess halves the remaining range. In 7 guesses you've covered all 100 numbers.

That's binary search: you have a sorted sequence (or one with a monotonic property), and at each step you ask one yes/no question that lets you throw away half. O(log n) total.

📚 Jargon Buster (Confusing Terms Explained)

Sorted / Monotonic
Values follow a pattern that lets you decide "go left" or "go right" from one comparison. Strict numerical sort is the obvious case; "first false then true" booleans (like First Bad Version) also count.
Invariant
The promise you keep across iterations — e.g., "answer lies in [L, R]." Choosing the right invariant fixes bugs about whether to write L < R or L <= R.
Half-open vs Closed intervals
[L, R] (closed): both endpoints can be the answer; loop ends when L > R. [L, R) (half-open): R is exclusive; loop ends when L == R. Both work; pick one and stick to it.
mid = L + (R − L) / 2
Use this instead of (L + R) / 2. The latter can overflow for large L + R. Both produce the same value when no overflow occurs.
Lower bound
Smallest index i such that arr[i] ≥ target. Equivalent to "where would target be inserted to keep the array sorted?"
Upper bound
Smallest index i such that arr[i] > target. Useful for counting (upper − lower = # occurrences of target).
Predicate
A boolean function f(i) that's false then true (or true then false). Binary search finds the boundary. This is the generalized form — most binary search problems reduce to "find the boundary of this predicate."
Oracle
An external API (like guess() or isBadVersion()) that answers comparison queries. You binary search using its answers.
Rotated array
A sorted array shifted by some offset: [4,5,6,7,0,1,2]. One half is always sorted — figure out which, then act accordingly.
Peak element
An element greater than its neighbors. Even on an unsorted array, you can binary search for a peak if you can decide "the peak is on this side."
Off-by-one
The most common bug. Always sanity-check with a 2-element input and a 1-element input. If both work, the loop is probably right.

🔎 When Should You Use Classic Binary Search?

  • The array (or answer space) is sorted or monotonic.
  • You're searching for an exact value, an insertion point, or a boundary.
  • The input size is large (O(log n) matters).
  • Brute force is O(n) and the constraints have an n ≤ 10⁵ or larger.
  • You have an oracle API that answers yes/no comparisons (guess, isBadVersion).

📈 The 5 Types of Classic Binary Search — Full Breakdown

① Exact Match (Standard Binary Search)

What it is: Find a target value in a sorted array; return its index, or −1 if absent.

Recognize it when:

  • "Given a sorted array and a target, return the index"
  • API-style oracle: "guess() returns −1/0/+1"

The decision rule:

  • If arr[mid] == target: return mid
  • If arr[mid] < target: L = mid + 1
  • If arr[mid] > target: R = mid − 1
Worked Example: Binary Search — find 9 in [−1, 0, 3, 5, 9, 12]
Closed interval [L, R]
Start
[-1L03M5912R]
L=0, R=5, mid=2 (val 3). 3 < 9 → L = mid+1 = 3
Step 1
[-1035L9M12R]
L=3, R=5, mid=4 (val 9). 9 == 9 → return 4
Code Template: 
int L = 0, R = nums.length - 1;
while (L <= R) {
    int mid = L + (R - L) / 2;
    if      (nums[mid] == target) return mid;
    else if (nums[mid] < target)  L = mid + 1;
    else                          R = mid - 1;
}
return -1;

② First-True Boundary (Insert Position / Lower Bound)

What it is: A predicate is false then true at some boundary. Binary search the smallest index where the predicate is true.

Recognize it when:

  • "Where should this value be inserted?" / "smallest index with arr[i] ≥ target"
  • "First bad version", "smallest letter greater than target"
  • "How many elements are < X" — count = lower_bound(X)

The decision rule:

  • If predicate(mid) is true: R = mid (might be the answer)
  • If predicate(mid) is false: L = mid + 1
  • Use half-open: L < R; answer is L at the end.
Worked Example: Search Insert Position — insert 5 into [1, 3, 5, 6]
Find smallest index i with nums[i] ≥ 5
Start
[1L35M6R]
L=0, R=4 (exclusive), mid=2. nums[2]=5 ≥ 5 → R = mid = 2
Step
[1L3M5R6]
L=0, R=2, mid=1. nums[1]=3 < 5 → L = mid+1 = 2
Done
L == R == 2
Answer: 2
Code Template: 
int L = 0, R = nums.length;        // half-open
while (L < R) {
    int mid = L + (R - L) / 2;
    if (nums[mid] >= target) R = mid;
    else                     L = mid + 1;
}
return L;

③ Rotated Sorted Array (Pivot-Aware Search)

What it is: Array is sorted then rotated, like [4,5,6,7,0,1,2]. One half (left of mid or right of mid) is always still sorted. Decide which, then act.

Recognize it when:

  • "Sorted array, rotated by unknown amount"
  • "Find target", "Find minimum", "Search if exists" in rotated input

The decision rule (search for target):

  • If nums[L] ≤ nums[mid]: left half is sorted
  • If target is in [nums[L], nums[mid]): search left; else search right
  • Symmetric when the right half is sorted
  • If duplicates are allowed: when nums[L] == nums[mid] == nums[R], you can't tell — shrink: L++; R--; worst-case O(n).
Worked Example: Search Rotated Array — find 0 in [4, 5, 6, 7, 0, 1, 2]
L=0, R=6, mid=3 (val 7)
Start
4L567M012R
left half [4..7] is sorted; target 0 not in [4,7) → search right: L=4
Step
45670L/M12R
L=4, R=6, mid=5 (val 1). Right half [1..2] sorted; 0 not in [1,2] → L stays, R = mid-1 = 4 … eventually find 0 at index 4
Code Template (search): 
int L = 0, R = nums.length - 1;
while (L <= R) {
    int mid = L + (R - L) / 2;
    if (nums[mid] == target) return mid;
    if (nums[L] <= nums[mid]) {              // left half sorted
        if (nums[L] <= target && target < nums[mid]) R = mid - 1;
        else                                          L = mid + 1;
    } else {                                  // right half sorted
        if (nums[mid] < target && target <= nums[R]) L = mid + 1;
        else                                          R = mid - 1;
    }
}
return -1;

④ Peak Finding (Mountain / Local Max)

What it is: An array isn't sorted, but it goes up then down (mountain) or has any local max. Compare arr[mid] to arr[mid+1]: rising means peak is to the right; falling means peak is at mid or to the left.

Recognize it when:

  • "Find a peak element" (any local max)
  • "Mountain array — find the peak / top"
  • "Single non-duplicate in sorted array" — index parity trick is the same idea

The decision rule:

  • If arr[mid] < arr[mid+1]: peak is to the right → L = mid + 1
  • Else peak is at mid or to the left → R = mid
  • Loop ends with L == R at the peak.
Worked Example: Peak Index in Mountain — [0, 2, 4, 6, 5, 3, 1]
Find the top of the mountain
Start
0L246M531R
L=0, R=6, mid=3 (val 6). arr[3]=6, arr[4]=5 → falling → R = mid = 3
Step
0L2M46R531
L=0, R=3, mid=1. arr[1]=2 < arr[2]=4 → rising → L = 2
Step
L=2, R=3, mid=2. arr[2]=4 < arr[3]=6 → L = 3
L == R == 3 → peak index 3
Code Template: 
int L = 0, R = nums.length - 1;
while (L < R) {
    int mid = L + (R - L) / 2;
    if (nums[mid] < nums[mid + 1]) L = mid + 1;
    else                           R = mid;
}
return L;

⑤ Numeric Binary Search (Math: sqrt, pow, perfect square)

What it is: The "array" is implicit — a numeric range. You binary search the answer space using a math predicate.

Recognize it when:

  • "Compute sqrt(n) without sqrt()" → search 0..n, check mid² vs n
  • "Is n a perfect square?" → same
  • "Compute pow(x, n)" → halving the exponent (different but related divide-and-conquer)
  • "Largest k rows from k(k+1)/2 ≤ n" → arithmetic predicate

The decision rule:

  • Use long when squaring or multiplying mid values (overflow trap!)
  • Otherwise same template as types 1 / 2 depending on whether you want exact match or boundary
Worked Example: Valid Perfect Square — num = 16
L=1, R=16
Step
mid=8, 8²=64 > 16 → R=7
Step
mid=4, 4²=16 == 16 → true
Answer: true
Code Template: 
long L = 1, R = num;
while (L <= R) {
    long mid = L + (R - L) / 2;
    long sq = mid * mid;
    if      (sq == num) return true;
    else if (sq < num)  L = mid + 1;
    else                R = mid - 1;
}
return false;

🔨 Universal Classic Binary Search Templates

// Type 1: exact match
int L = 0, R = n - 1;
while (L <= R) {
    int mid = L + (R - L) / 2;
    if      (nums[mid] == target) return mid;
    else if (nums[mid] < target)  L = mid + 1;
    else                          R = mid - 1;
}
return -1;

// Type 2: first true (lower bound)
int L = 0, R = n;
while (L < R) {
    int mid = L + (R - L) / 2;
    if (predicate(mid)) R = mid;
    else                L = mid + 1;
}
return L;   // == n if predicate never true
