P03 — Kth Smallest Element in a Sorted Matrix

Medium • LC #378 • Pattern: Binary Search on Value + Count ≤ v

📝 The Problem

Matrix is sorted both row-wise and column-wise ascending. Return the k-th smallest element.

Example: [[1,5,9],[10,11,13],[12,13,15]], k = 8 → 13

📚 Jargon Buster

BS on the answer
Search the value range [matrix[0][0], matrix[n-1][n-1]]. For each candidate v, count how many entries ≤ v.
Count ≤ v in sorted matrix
Walk from top-right (or bottom-left); each row contributes a known count via the column pointer. O(n) per check.
Smallest v with count ≥ k
The answer. Standard "smallest valid value" binary search (lower-bound flavor).

🌟 In Layman's Terms

Guess a value. Count how many matrix cells are ≤ that guess. If too few, guess bigger. If enough, your guess is at least as big as the answer — shrink it.

⚡ The Aha Moment

You don't sort the matrix. You binary search the value and use a clever O(n) count thanks to the sorted rows/columns.

🔧 Algorithm

  1. lo = matrix[0][0], hi = matrix[n-1][n-1].
  2. While lo < hi: mid = (lo + hi)/2; cnt = countLE(matrix, mid).
  3. If cnt < k: lo = mid + 1. Else hi = mid.
  4. Return lo.

☕ Java Solution

public int kthSmallest(int[][] m, int k) {
    int n = m.length, lo = m[0][0], hi = m[n - 1][n - 1];
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        int cnt = 0, j = n - 1;
        for (int i = 0; i < n; i++) {
            while (j >= 0 && m[i][j] > mid) j--;
            cnt += j + 1;
        }
        if (cnt < k) lo = mid + 1;
        else         hi = mid;
    }
    return lo;
}

⏳ Complexity

Time
O(n · log(max−min))
Space
O(1)

📈 LB/UB Pattern

BS on the Answer: The reusable trick for k-th smallest in structured data — sorted matrix, multiplication table, prime fractions, pair distances. Same skeleton, different count routine.
Key Insight: The answer is always an actual entry in the matrix (because we shrink to the smallest valid value), so no rounding errors.
