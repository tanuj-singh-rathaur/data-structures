P19 — Online Election

Medium • LC #911 • Pattern: Precompute Leader Per Time + UB on Query

📝 The Problem

People vote over time. Implement q(t) returning who was leading at time t (most recent leader wins ties).

Example: persons=[0,1,1,0,0,1,0], times=[0,5,10,15,20,25,30]; q(3)→0, q(12)→1

📚 Jargon Buster

Precompute leaders
Sweep events left-to-right; maintain vote counts; leader array stores who was leading after each event.
Most recent leader wins ties
When current votes equal the max, the current voter takes the lead.
UB on times
For a query t, find upperBound(times, t) − 1: the index of the most recent event at or before t.

🌟 In Layman's Terms

Precompute "who was leading after each event." When a query asks about time t, binary search for the most recent event ≤ t, then read the leader from the array.

⚡ The Aha Moment

The leader changes only at event times. Once precomputed, every query is a single UB.

🔧 Algorithm

  1. Constructor: walk events; maintain counts and current leader; leader[i] = leader after event i.
  2. q(t): idx = upperBound(times, t) − 1; return leader[idx].

☕ Java Solution

class TopVotedCandidate {
    int[] times, leader;
    public TopVotedCandidate(int[] persons, int[] times) {
        this.times = times;
        int n = persons.length;
        this.leader = new int[n];
        int[] count = new int[n];
        int top = -1;
        for (int i = 0; i < n; i++) {
            int p = persons[i];
            count[p]++;
            if (top == -1 || count[p] >= count[top]) top = p;
            leader[i] = top;
        }
    }
    public int q(int t) {
        int L = 0, R = times.length;
        while (L < R) {
            int mid = L + (R - L) / 2;
            if (times[mid] > t) R = mid;
            else                L = mid + 1;
        }
        return leader[L - 1];
    }
}

⏳ Complexity

Constructor
O(n)
q
O(log n)
Space
O(n)

📈 LB/UB Pattern

Precompute + Per-Query UB: Heavy lifting at construction; each query is a simple boundary search.
Key Insight: Snapshots of state at well-defined timestamps make point-in-time queries cheap — binary search the timeline.
