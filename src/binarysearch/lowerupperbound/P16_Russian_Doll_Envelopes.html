P16 — Russian Doll Envelopes

Hard • LC #354 • Pattern: Sort with Tie-Break, then LIS on Heights

📝 The Problem

Each envelope has a width and a height. One fits inside another only if both dimensions are strictly smaller. Return the longest nested chain.

Example: [[5,4],[6,4],[6,7],[2,3]] → 3

📚 Jargon Buster

Tie-break sort
Sort by width ascending; for equal widths, sort heights descending. This prevents same-width envelopes from forming a fake chain.
LIS on heights
After sorting, run patience-sort LIS on the heights array. That's the answer.

🌟 In Layman's Terms

Sort by width. For ties on width, put the bigger height first (so they can't stack). Now run LIS on heights — same-width pairs are naturally excluded.

⚡ The Aha Moment

The descending tie-break is the crux — it prevents same-width envelopes from being counted as a chain when running 1D LIS.

🔧 Algorithm

  1. Sort: width asc; ties → height desc.
  2. Run LIS on heights using patience sort.

☕ Java Solution

public int maxEnvelopes(int[][] env) {
    java.util.Arrays.sort(env, (a, b) -> a[0] != b[0] ? a[0] - b[0] : b[1] - a[1]);
    int[] tails = new int[env.length];
    int size = 0;
    for (int[] e : env) {
        int x = e[1], L = 0, R = size;
        while (L < R) {
            int mid = L + (R - L) / 2;
            if (tails[mid] < x) L = mid + 1;
            else                R = mid;
        }
        tails[L] = x;
        if (L == size) size++;
    }
    return size;
}

⏳ Complexity

Time
O(n log n)
Space
O(n)

📈 LB/UB Pattern

Sort + LIS: Reducing a 2D ordering problem to a 1D LIS via a careful sort with descending tie-break.
Key Insight: Always remember the descending tie-break. Without it, equal-width envelopes form an invalid 2D chain.
