P02 — Quick Sort

Medium • LC #912 • Pattern: Pivot Partition + Recurse Both Sides

📝 The Problem

Implement quicksort: in-place sort with O(n log n) average.

📚 Jargon Buster

Pivot
The element used to split the array; everything ≤ pivot goes left, ≥ pivot right.
Lomuto vs Hoare
Two partition schemes. Hoare is faster and handles duplicates better.
Randomised Pivot
Pick pivot uniformly at random to avoid O(n²) worst case on sorted inputs.

🌟 In Layman's Terms

Choose a number. Move smaller numbers to its left, larger to its right. Then quicksort each side.

⚡ The Aha Moment

No merge step needed — partition is the combine step (in-place).

🔧 Algorithm

  1. If lo < hi: choose pivot (random), partition; recurse left, recurse right.

☕ Java Solution (Hoare)

public int[] sortArray(int[] nums) {
    qs(nums, 0, nums.length - 1);
    return nums;
}
private void qs(int[] a, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    qs(a, lo, p);
    qs(a, p + 1, hi);
}
private int partition(int[] a, int lo, int hi) {
    int pivot = a[lo + (hi - lo) / 2];
    int i = lo - 1, j = hi + 1;
    while (true) {
        do i++; while (a[i] < pivot);
        do j--; while (a[j] > pivot);
        if (i >= j) return j;
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}

⏳ Complexity

Time
O(n log n) avg / O(n²) worst
Space
O(log n) stack

📈 D&C Pattern

Partition Skeleton: The partition routine doubles as Quickselect's workhorse and 3-way partition (Dutch flag).
Key Insight: Quicksort is in-place; merge sort is stable. Pick by constraint.
