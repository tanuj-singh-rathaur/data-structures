P06 — Pow(x, n)

Medium • LC #50 • Pattern: xn = (xn/2)2 · xn mod 2

📝 The Problem

Compute xn (real x, integer n). Must handle negative n and INT_MIN.

📚 Jargon Buster

Fast Exponentiation
By squaring: each recursion halves the exponent ⇒ O(log n) multiplications.
INT_MIN Pitfall
−Integer.MIN_VALUE overflows. Convert n to long first.

🌟 In Layman's Terms

Instead of multiplying x by itself n times, recursively compute xn/2 then square it. Multiply by x once more if n is odd.

⚡ The Aha Moment

Negative n: compute positive case, return 1/result. Or convert n to long up front to avoid overflow.

🔧 Algorithm

  1. If n < 0: return 1.0 / pow(x, −n).
  2. If n == 0: return 1.
  3. half = pow(x, n / 2); return n % 2 == 0 ? half * half : half * half * x.

☕ Java Solution

public double myPow(double x, int n) {
    long N = n;
    if (N < 0) { x = 1 / x; N = -N; }
    double ans = 1.0;
    while (N > 0) {
        if ((N & 1) == 1) ans *= x;
        x *= x;
        N >>= 1;
    }
    return ans;
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 D&C Pattern

Halve-Exponent: Iterative bit-walk replaces recursion when stack is a concern.
Key Insight: Whenever a parameter halves each step, depth ⇒ O(log n). Recognise the pattern beyond just powers.
