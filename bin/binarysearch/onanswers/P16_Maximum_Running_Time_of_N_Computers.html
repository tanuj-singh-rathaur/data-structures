P16 — Max Running Time of N Computers

Hard • LC #2141 • Pattern: BS time t · predicate Σ min(batt[i], t) ≥ n·t

📝 The Problem

You have batteries (extra) and n computers. Each computer needs 1 battery's-worth of power per minute. Swap freely. Max time all n computers can run simultaneously.

📚 Jargon Buster

Power Budget
Each battery contributes min(batt[i], t) to a t-minute run (a battery can't power for more than its own value).
Feasibility at t
Σ min(batt[i], t) ≥ n · t.

🌟 In Layman's Terms

Guess a run time. Cap each battery's contribution to t. Sum. Compare with n · t. Binary search max feasible t.

⚡ The Aha Moment

You can't use a 5-unit battery for 10 minutes — hence the min(b, t) cap. That's the only twist.

🔧 Algorithm

  1. lo = 1, hi = sum(batteries) / n.
  2. BS max t with Σ min(b[i], t) ≥ n · t.

☕ Java Solution

public long maxRunTime(int n, int[] batt) {
    long lo = 1, hi = 0;
    for (int b : batt) hi += b;
    hi /= n;
    while (lo < hi) {
        long mid = lo + (hi - lo + 1) / 2;
        long total = 0;
        for (int b : batt) total += Math.min(b, mid);
        if (total >= (long) n * mid) lo = mid;
        else                          hi = mid - 1;
    }
    return lo;
}

⏳ Complexity

Time
O(m log sum)
Space
O(1)

📈 BS-on-Answers Pattern

Cap-and-Sum Predicate: When per-item contribution is capped by the candidate, use min(value, candidate) summation.
Key Insight: The cap min(b, t) is the bridge that makes the predicate non-trivial yet still monotone.
