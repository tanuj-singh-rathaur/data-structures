P07 — Find the Duplicate Number

Medium • LC #287 • Pattern: BS on Value + Count

📝 The Problem

An array of n+1 ints, each in [1..n]. Exactly one value appears more than once. Find it without modifying the array, O(1) extra space.

Example: [1, 3, 4, 2, 2] → 2

📚 Jargon Buster

Pigeonhole insight
If you count how many nums ≤ v, in a duplicate-free array the count would be exactly v. With a duplicate ≤ v, the count exceeds v.
BS on value
Search v in [1, n]. Smallest v with count(≤ v) > v is the duplicate.

🌟 In Layman's Terms

Guess a value v. Count how many array elements are ≤ v. If that count is bigger than v, the duplicate is in [1..v]. Otherwise it's in [v+1..n]. Binary search.

⚡ The Aha Moment

The "count ≤ v" function is monotonic in v but jumps faster than v where the duplicate sits.

🔧 Algorithm

  1. L = 1, R = n.
  2. While L < R: mid; cnt = count of nums ≤ mid.
  3. If cnt > mid: R = mid. Else L = mid + 1.

☕ Java Solution

public int findDuplicate(int[] nums) {
    int L = 1, R = nums.length - 1;
    while (L < R) {
        int mid = L + (R - L) / 2, cnt = 0;
        for (int x : nums) if (x <= mid) cnt++;
        if (cnt > mid) R = mid;
        else           L = mid + 1;
    }
    return L;
}

⏳ Complexity

Time
O(n log n)
Space
O(1)

📈 LB/UB Pattern

BS on Value Range: Search the answer's numeric value. Monotonic count predicate makes lower bound directly applicable.
Key Insight: Whenever values are bounded and the count function is monotonic, binary search the value range — no need to touch indices.
