P04 — Find K Closest Elements

Medium • LC #658 • Pattern: Binary Search the Window's Left Boundary

📝 The Problem

Given a sorted array arr, integer k, and integer x, return the k closest integers to x, sorted ascending. Tie → smaller integer.

Example: arr = [1,2,3,4,5], k = 4, x = 3 → [1, 2, 3, 4]

📚 Jargon Buster

Result window
Since the array is sorted, the k closest values are always a contiguous slice [L..L+k−1]. We binary search the left boundary L.
Comparison rule
For candidate L, compare x − arr[L] vs arr[L+k] − x. If the right end is closer (or equal), shift window right.
Range of L
L ∈ [0, n−k]. Binary search this small range.

🌟 In Layman's Terms

The answer is a contiguous slice of length k. Binary search where its left edge starts — at each candidate L, compare how far the left edge is from x vs how far the position just past the right edge is.

⚡ The Aha Moment

Don't filter or sort by distance — binary search a single index (the window's left edge).

🔧 Algorithm

  1. L = 0, R = n − k. While L < R: mid = (L+R)/2.
  2. If x − arr[mid] > arr[mid+k] − x: L = mid + 1. Else R = mid.
  3. Return arr[L..L+k−1].

☕ Java Solution

public List<Integer> findClosestElements(int[] arr, int k, int x) {
    int L = 0, R = arr.length - k;
    while (L < R) {
        int mid = L + (R - L) / 2;
        if (x - arr[mid] > arr[mid + k] - x) L = mid + 1;
        else                                  R = mid;
    }
    List<Integer> res = new ArrayList<>(k);
    for (int i = 0; i < k; i++) res.add(arr[L + i]);
    return res;
}

⏳ Complexity

Time
O(log(n − k) + k)
Space
O(k)

📈 LB/UB Pattern

Binary Search the Window's Left Boundary: When the answer is "k consecutive sorted elements," binary search the left edge instead of filtering by distance.
Key Insight: The comparison x − arr[mid] vs arr[mid+k] − x implicitly handles ties (≤ keeps the smaller-index window, giving lex-smaller answer).
