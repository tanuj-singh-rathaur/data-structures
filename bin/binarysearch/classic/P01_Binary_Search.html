P01 — Binary Search

Easy • LC #704 • Pattern: Standard Binary Search

📝 The Problem

Given a sorted ascending array nums and a value target, return its index or −1.

Example: nums = [-1, 0, 3, 5, 9, 12], target = 9 → 4

📚 Jargon Buster

Sorted ascending
Smaller values come first. The cornerstone — without sortedness, binary search can't decide which half to discard.
Closed interval [L, R]
Both endpoints are valid candidates. Loop condition: L <= R. Update: L = mid+1 or R = mid-1.
mid = L + (R − L)/2
Overflow-safe form of "midpoint." For very large L+R, (L+R)/2 may wrap around to a negative.

🌟 In Layman's Terms

Look at the middle of the array. If it's the target — done. If it's smaller — the answer is to the right. If larger — to the left. Repeat on the half you kept. Each step halves the search space.

⚡ The Aha Moment

You don't have to scan all n items. Just log₂ n decisions, each cutting the range in half.

🔧 Algorithm

  1. Initialize L = 0, R = n − 1.
  2. While L ≤ R: compute mid; compare.
  3. Return mid on match; adjust L or R otherwise.

☕ Java Solution

public int search(int[] nums, int target) {
    int L = 0, R = nums.length - 1;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        if      (nums[mid] == target) return mid;
        else if (nums[mid] < target)  L = mid + 1;
        else                          R = mid - 1;
    }
    return -1;
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 Binary Search Pattern

Exact Match: The textbook template. Mastering this is a prerequisite for every other variation.
Key Insight: Stick to one interval style (closed [L, R] or half-open [L, R)) and update consistently. Most off-by-one bugs come from mixing the two.
