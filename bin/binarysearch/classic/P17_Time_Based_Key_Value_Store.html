P17 — Time Based Key-Value Store

Medium • LC #981 • Pattern: HashMap + Per-Key Binary Search

📝 The Problem

Design a class that supports set(key, value, timestamp) and get(key, timestamp). get returns the value with the largest timestamp ≤ the query, or empty string if none.

Guarantee: set calls for a key arrive in increasing timestamp order.

📚 Jargon Buster

Per-key sorted list
HashMap from key to list of (timestamp, value). Because sets arrive sorted, the list stays sorted automatically.
Largest ≤ query
This is "upper bound minus one" or equivalently "rightmost position with timestamp ≤ query." Binary search.

🌟 In Layman's Terms

Each key has its own timeline of values. On a get, binary search that timeline for the latest entry whose timestamp doesn't exceed the query.

⚡ The Aha Moment

Don't store an array of all (key, timestamp) tuples and search globally. Bucket by key first; each bucket is its own sorted sequence to search in O(log n).

🔧 Algorithm

  1. set: append (timestamp, value) to the key's list.
  2. get: binary search the list for largest timestamp ≤ query; return its value, or "" if none.

☕ Java Solution

class TimeMap {
    Map<String, List<int[]>> tsMap = new HashMap<>();
    Map<String, List<String>> valMap = new HashMap<>();

    public void set(String key, String value, int timestamp) {
        tsMap.computeIfAbsent(key, k -> new ArrayList<>()).add(new int[]{timestamp});
        valMap.computeIfAbsent(key, k -> new ArrayList<>()).add(value);
    }
    public String get(String key, int timestamp) {
        List<int[]> ts = tsMap.get(key);
        if (ts == null) return "";
        int L = 0, R = ts.size();
        while (L < R) {
            int mid = L + (R - L) / 2;
            if (ts.get(mid)[0] > timestamp) R = mid;
            else                            L = mid + 1;
        }
        return L == 0 ? "" : valMap.get(key).get(L - 1);
    }
}

⏳ Complexity

set
O(1) amortized
get
O(log n)
Space
O(N)

📈 Binary Search Pattern

HashMap + Per-Key Binary Search: Group entries first, then binary search inside the relevant group. Standard design for time-series lookups.
Key Insight: "Largest timestamp ≤ query" is upper bound minus one. The boundary template handles it cleanly — just return the index before L.
