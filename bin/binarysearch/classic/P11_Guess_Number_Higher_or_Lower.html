P11 — Guess Number Higher or Lower

Easy • LC #374 • Pattern: Exact Match via Oracle

📝 The Problem

The system picked a number between 1 and n. You call guess(num) which returns −1 / 0 / +1. Find the number with minimum calls.

Example: n = 10, pick = 6 → 6

📚 Jargon Buster

Oracle API
You don't see the array; you only call guess(num) for one of three outcomes.
Three-way decision
Map guess() return directly: 0 → done; −1 → guess too high → R = mid−1; +1 → guess too low → L = mid+1.

🌟 In Layman's Terms

You're playing "higher or lower" with a friend who picked a number 1–n. Always guess the middle of your remaining range. The hint tells you which half to keep.

⚡ The Aha Moment

Pure binary search. The oracle is your nums[mid] vs target check.

🔧 Algorithm

  1. L = 1, R = n. While L ≤ R: mid = L + (R−L)/2.
  2. res = guess(mid). 0 → return mid; +1 → L = mid+1; −1 → R = mid−1.

☕ Java Solution

public int guessNumber(int n) {
    int L = 1, R = n;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        int res = guess(mid);
        if      (res == 0) return mid;
        else if (res == 1) L = mid + 1;
        else               R = mid - 1;
    }
    return -1;
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 Binary Search Pattern

Exact Match via Oracle: When the comparison comes from an API rather than an array index, the binary search template is otherwise identical.
Key Insight: Don't get fooled by API problems — the oracle is just a comparator. Plug it into the template.
