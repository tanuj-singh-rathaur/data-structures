P06 — Search in Rotated Sorted Array II

Medium • LC #81 • Pattern: Rotated Search with Duplicates Shrink

📝 The Problem

Same as P04, but values may repeat. Return true / false for whether target is present.

Example: [2, 5, 6, 0, 0, 1, 2], target = 0 → true

📚 Jargon Buster

Ambiguous case
When nums[L] == nums[mid] == nums[R], both halves look sorted — you can't tell which side has the target.
Shrink ends
In the ambiguous case, just do L++; R--. You haven't lost the answer because the equal endpoints can be skipped.
Worst-case O(n)
If the whole array is one value, every step shrinks by 1. Duplicates break the log-n guarantee.

🌟 In Layman's Terms

Same as P04, but every now and then you can't tell which side the pivot is on (because the ends and the mid look the same). When that happens, just shrink both ends by one and try again.

⚡ The Aha Moment

Duplicates break the "one half is sorted" invariant only in a specific case — both endpoints equal the mid. Handle it with a tiny linear step; the rest of the algorithm stays binary.

🔧 Algorithm

  1. Same as P04, but at the top of each loop iteration, if nums[L] == nums[mid] == nums[R], do L++; R-- and continue.

☕ Java Solution

public boolean search(int[] nums, int target) {
    int L = 0, R = nums.length - 1;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        if (nums[mid] == target) return true;
        if (nums[L] == nums[mid] && nums[mid] == nums[R]) {
            L++; R--;
        } else if (nums[L] <= nums[mid]) {
            if (nums[L] <= target && target < nums[mid]) R = mid - 1;
            else                                            L = mid + 1;
        } else {
            if (nums[mid] < target && target <= nums[R])   L = mid + 1;
            else                                            R = mid - 1;
        }
    }
    return false;
}

⏳ Complexity

Time
O(log n) avg, O(n) worst
Space
O(1)

📈 Binary Search Pattern

Rotated Search with Duplicate Shrink: Same as P04 plus a small "give up the ambiguous endpoints" step. The rest of the search remains O(log n) per side.
Key Insight: When duplicates make a binary-search decision impossible, falling back to a one-step shrink is OK — you keep correctness and only lose log-n in the worst pathological case.
