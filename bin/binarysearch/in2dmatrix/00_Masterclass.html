💡 What Is Binary Search on 2D? (Layman's Explanation)

A matrix is just a 2D array, but you don't always have to scan every cell. If the matrix has any kind of order (rows sorted, columns sorted, both sorted, monotone diagonal, etc.) you can usually find or count things in O(log n + log m), O(m + n), or O((m + n) log V).

Five reliable techniques carry almost every grid-search problem: flatten the matrix into one sorted run, walk the staircase, binary search the answer value, binary search a boundary (row, column, or day), and combine BS with BFS/DFS/Union-Find for path-on-grid problems.

📚 Jargon Buster (Confusing Terms Explained)

Row-sorted matrix
Each row is sorted ascending; rows are independent. Each row is its own sorted array.
Row + Column sorted
Each row is ascending AND each column is ascending. The classic "Search a 2D Matrix II" structure.
Strictly sorted (treat-as-1D)
If the matrix has the property "last value of row i < first value of row i+1," the whole matrix flattens into a single sorted sequence. Standard binary search applies on index r * cols + c.
Staircase walk
Start at top-right (or bottom-left). At each cell, the comparison tells you to step left or down (or right/up). Each step rules out an entire row or column.
BS on the answer
You search a value, not an index. For each candidate v, you count cells satisfying the predicate; smallest v with count ≥ k is the answer.
BS on a day / level / threshold
For "grid evolves over time" problems (Last Day to Cross, Swim in Rising Water, Path with Min Effort), binary search the time/threshold and check reachability with BFS / DFS / Union-Find.
2D prefix sums
P[r][c] = sum of all cells in [0..r−1] × [0..c−1]. Allows O(1) submatrix sums. Pairs cleanly with BS on size (P10).
Row compression
Fix two row indices r1, r2; collapse each column to its sum across rows r1..r2. Reduces 2D problems to 1D (P09).
Diagonal monotonicity
Some problems' interesting quantity changes monotonically along diagonals (find peak II, smallest rectangle of black pixels).

🔎 When Should You Use Binary Search on 2D?

  • "Find / does X exist in a sorted matrix" → flatten or staircase
  • "Count negatives in sorted matrix" / "leftmost 1 per row" → staircase
  • "k-th smallest / smallest with property" in a sorted matrix → BS on the answer
  • "Max submatrix sum ≤ K" → row compression + BS on prefix
  • "Path on grid with min/max edge weight" → BS the threshold + reachability check
  • "Maximum side of square sum ≤ T" → 2D prefix + BS on side length

📈 The 5 Types of 2D Binary Search — Full Breakdown

① Flatten to 1D Binary Search

What it is: The matrix is strictly sorted (row by row, last of row i < first of row i+1). Pretend it's one big sorted array of length m·n. Standard BS on index k, with row = k / n, col = k % n.

Recognize it when:

  • "Search a 2D Matrix" (LC 74): the explicit "rows concatenate" guarantee
  • You're told both: rows sorted AND first-of-next-row > last-of-this-row

The decision rule:

  • L = 0, R = m·n − 1
  • mid → (mid / n, mid % n) → compare to target
Code Template: 
public boolean searchMatrix(int[][] m, int target) {
    int rows = m.length, cols = m[0].length;
    int L = 0, R = rows * cols - 1;
    while (L <= R) {
        int mid = L + (R - L) / 2;
        int v = m[mid / cols][mid % cols];
        if      (v == target) return true;
        else if (v < target)  L = mid + 1;
        else                  R = mid - 1;
    }
    return false;
}

② Staircase Walk (Row + Column Sorted)

What it is: Each row sorted, each column sorted, but no flat order. Start at the top-right (or bottom-left). The cell value vs target tells you which whole row/column to discard.

Recognize it when:

  • "Sorted both ways" matrix (LC 240)
  • "Count negatives in sorted matrix"
  • "Leftmost column with a 1" (binary matrix; rows sorted)

The decision rule (top-right start):

  • If m[r][c] == target: found
  • If m[r][c] > target: c-- (discard column)
  • If m[r][c] < target: r++ (discard row)
Code Template (Search 2D II): 
public boolean searchMatrix(int[][] m, int target) {
    int r = 0, c = m[0].length - 1;
    while (r < m.length && c >= 0) {
        if      (m[r][c] == target) return true;
        else if (m[r][c] > target)  c--;
        else                        r++;
    }
    return false;
}

③ Binary Search the Answer (Value Range)

What it is: You can't access the k-th smallest directly, but you can count entries ≤ a candidate value efficiently (linear or log). Binary search the value range.

Recognize it when:

  • "K-th smallest sum" / "K-th smallest pair" / "K-th smallest in matrix"
  • "Maximum side / area / sum subject to ≤ K" (BS on size or sum)

The pattern:

  • lo = minPossible, hi = maxPossible
  • For each mid, count(≤ mid) via problem-specific routine
  • Adjust lo/hi to find boundary; answer = lo at the end
Code Template (BS value with count helper): 
int lo = minVal, hi = maxVal;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (count(mid) < k) lo = mid + 1;
    else                hi = mid;
}
return lo;

④ Binary Search Threshold + Grid Reachability

What it is: The grid evolves with a parameter (water level, day, max effort). Binary search the threshold; for each candidate run a BFS / DFS / Union-Find to check if (start) can reach (end).

Recognize it when:

  • "Last day you can still cross" / "Swim in Rising Water"
  • "Path with minimum effort" / "Path with maximum minimum value"

The pattern:

  • Binary search t in [low, high]
  • Check connectivity using only cells satisfying t
  • O((m·n) · log(range))
Code Template (sketch): 
int lo = ..., hi = ...;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (canCross(grid, mid)) hi = mid;
    else                     lo = mid + 1;
}
return lo;

⑤ Transform to 1D + Sorted Lower Bound

What it is: Define a derived quantity (e.g. d[i] = nums1[i] − nums2[i]); sort or maintain it; answer queries by binary search on the sorted helper.

Recognize it when:

  • "Number of pairs satisfying inequality" / "Count pairs in two arrays"
  • "Most beautiful item for each query" — sort by price, prefix-max beauty, LB per query
  • "Minimum absolute sum difference" — sort nums1, LB nums2[i] to find best replacement
  • "Find peak in 2D matrix" — binary search the column
Code Template (Min Abs Sum Diff): 
int[] sorted = nums1.clone();
java.util.Arrays.sort(sorted);
long total = 0;
int bestSave = 0;
for (int i = 0; i < n; i++) {
    int d = Math.abs(nums1[i] - nums2[i]);
    total += d;
    int idx = lowerBound(sorted, nums2[i]);
    if (idx < n) bestSave = Math.max(bestSave, d - Math.abs(sorted[idx] - nums2[i]));
    if (idx > 0) bestSave = Math.max(bestSave, d - Math.abs(sorted[idx - 1] - nums2[i]));
}
return (int) ((total - bestSave) % 1_000_000_007);
