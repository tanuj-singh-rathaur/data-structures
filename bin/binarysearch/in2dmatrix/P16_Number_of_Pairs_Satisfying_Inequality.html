P16 — Number of Pairs Satisfying Inequality

Hard • LC #2426 • Pattern: Transform to d[i] − d[j] ≤ diff + Sorted LB

📝 The Problem

Count pairs i < j with nums1[i] − nums1[j] ≤ nums2[i] − nums2[j] + diff.

📚 Jargon Buster

Transform
Let d[i] = nums1[i] − nums2[i]. The inequality becomes d[i] − d[j] ≤ diff i.e. d[i] ≤ d[j] + diff.
Sorted-insertion + UB
Maintain a sorted helper. For each j, count of i < j satisfying the inequality = upper-bound of d[j] + diff in the sorted helper.

🌟 In Layman's Terms

Build d[i] = nums1[i] − nums2[i]. Walk j from 0 onward. For each j, count how many earlier d[i] are ≤ d[j] + diff via upper bound on a sorted helper.

⚡ The Aha Moment

The transform turns a 2-array condition into a 1-array sorted-insertion problem.

🔧 Algorithm

  1. Compute d[].
  2. For j = 0..n−1: UB(sorted, d[j] + diff) gives count of valid i < j; sorted-insert d[j].

📈 2D Pattern

Transform + Sorted UB: The "d[i] − d[j] ≤ diff" trick reduces 2D inequalities to 1D sorted-helper counting.
Key Insight: Whenever the inequality involves both arrays linearly, define a single derived array; the per-pair constraint becomes 1D.
