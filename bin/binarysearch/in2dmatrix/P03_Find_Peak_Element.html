P03 — Find Peak Element

Medium • LC #162 • Pattern: BS Anchor for 2D Variant

📝 The Problem

Array; element is a peak if strictly greater than both neighbors. Find any peak index in O(log n).

Example: [1, 2, 3, 1] → 2

📚 Jargon Buster

Peak in any array
Edges count as having −∞ neighbors. So a strictly increasing then decreasing array always has at least one peak.
Why this is in the 2D folder
This 1D problem is the foundation for the 2D "Find a Peak Element II" (P05), which binary searches one column and uses 1D peak logic on it.

🌟 In Layman's Terms

Compare mid to mid+1. Slope up → peak to the right. Slope down → peak at mid or to the left.

⚡ The Aha Moment

Not the whole array but the slope is monotone enough — binary search the rising side.

🔧 Algorithm

  1. L = 0, R = n − 1.
  2. While L < R: mid; if nums[mid] < nums[mid+1]: L = mid + 1. Else R = mid.

☕ Java Solution

public int findPeakElement(int[] nums) {
    int L = 0, R = nums.length - 1;
    while (L < R) {
        int mid = L + (R - L) / 2;
        if (nums[mid] < nums[mid + 1]) L = mid + 1;
        else                            R = mid;
    }
    return L;
}

⏳ Complexity

Time
O(log n)
Space
O(1)

📈 2D Pattern

1D Peak Anchor: The base case for 2D peak. Once you can find a peak in a 1D slice (a column), the 2D version reduces to binary searching the column with the maximum.
Key Insight: Binary search doesn't require global sortedness — only a local "slope is rising" predicate. That's what makes this O(log n) on an arbitrary array.
