P04 — Longest Substring with At Most K Distinct Characters

Medium • LC #340 • Pattern: Variable Window + Distinct Counter

📝 The Problem

Return the length of the longest substring containing at most K distinct characters.

Example: s = "eceba", K = 2 → 3 ("ece")

📚 Jargon Buster

Distinct count
Number of different characters currently in the window. With a HashMap, that's map.size().
Remove on zero
When a count drops to 0 on shrink, remove the key. Otherwise map.size() overcounts and the loop misbehaves.

🌟 In Layman's Terms

Grow the window to the right; if it ever contains more than K distinct characters, shrink from the left until you're back to K. Track the max length seen.

⚡ The Aha Moment

Distinct-character count is map size. As long as you remove keys when counts hit zero, that scalar is your invariant.

🔧 Algorithm

  1. map = HashMap. L = 0, best = 0.
  2. For R: map[s[R]]++. While map.size() > K: decrement map[s[L]], remove if 0, L++.
  3. best = max(best, R - L + 1).

☕ Java Solution

public int lengthOfLongestSubstringKDistinct(String s, int K) {
    Map<Character, Integer> count = new HashMap<>();
    int L = 0, best = 0;
    for (int R = 0; R < s.length(); R++) {
        count.merge(s.charAt(R), 1, Integer::sum);
        while (count.size() > K) {
            char lc = s.charAt(L);
            count.merge(lc, -1, Integer::sum);
            if (count.get(lc) == 0) count.remove(lc);
            L++;
        }
        best = Math.max(best, R - L + 1);
    }
    return best;
}

⏳ Complexity

Time
O(n)
Space
O(K)

📈 Sliding Window Pattern

Variable Window + Distinct Counter: The reusable "at-most-K distinct" template. Same pattern with K=2 is Fruit Into Baskets; with K = arbitrary, this problem.
Key Insight: The most common bug is forgetting to remove the key when its count hits zero. Without it, map.size() would be wrong and the loop would never terminate properly.
