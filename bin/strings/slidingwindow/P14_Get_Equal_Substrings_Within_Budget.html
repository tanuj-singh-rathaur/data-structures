P14 — Get Equal Substrings Within Budget

Medium • LC #1208 • Pattern: Variable Window with Cost Budget

📝 The Problem

Given s, t (same length) and maxCost, return the longest substring length where the total conversion cost (sum of |s[i] − t[i]| over the window) is ≤ maxCost.

Example: s = "abcd", t = "bcdf", maxCost = 3 → 3

📚 Jargon Buster

Conversion cost
|ascii(s[i]) − ascii(t[i])|. Each index has its own cost, independent of others.
Budget
Total cost across the window can't exceed maxCost.
Non-negative metric
Costs are ≥ 0, so the sum is monotonic on grow/shrink — classic sliding window territory.

🌟 In Layman's Terms

Each index has a price tag. Find the longest window whose total price is within your budget. Grow R; shrink L if you blow the budget.

⚡ The Aha Moment

Costs are non-negative, so growing the window only increases the cost. That monotonicity is what lets the sliding window be correct.

🔧 Algorithm

  1. L = 0, sum = 0, best = 0.
  2. For R: sum += |s[R] − t[R]|. While sum > maxCost: sum -= |s[L] − t[L]|; L++.
  3. best = max(best, R - L + 1).

☕ Java Solution

public int equalSubstring(String s, String t, int maxCost) {
    int L = 0, sum = 0, best = 0;
    for (int R = 0; R < s.length(); R++) {
        sum += Math.abs(s.charAt(R) - t.charAt(R));
        while (sum > maxCost) {
            sum -= Math.abs(s.charAt(L) - t.charAt(L));
            L++;
        }
        best = Math.max(best, R - L + 1);
    }
    return best;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Variable Window with Budget: Same skeleton as "Min Size Subarray Sum" — budget instead of target, longest instead of shortest. Different optimization direction, same template.
Key Insight: "Longest with cost ≤ K" and "shortest with sum ≥ K" share the same shrink logic. Only the goal (max vs min length) and the trigger (cost > K vs sum ≥ K) differ.
