💡 What Is Sliding Window on Strings? (Layman's Explanation)

A window is a contiguous slice [L..R] of the string. The pointers walk forward; the window state (character counts, distinct count, vowel count, …) updates incrementally as characters enter on the right and leave on the left. One pass — O(n).

For strings the “state” is almost always a frequency map (often a 26-slot int array for lowercase letters).

📚 Jargon Buster (Confusing Terms Explained)

Substring
A contiguous slice of a string (no skipping).
Anagram / Permutation
Same characters with the same counts, possibly reordered. "abc" and "bca" are anagrams.
Distinct count
How many different characters are currently in the window. With a HashMap, this is map.size().
Frequency map (int[26])
An array of length 26 where count[c-'a'] = occurrences of c in the window. Constant-time updates.
Have / Need counters
Used in “contains all of t” problems. need = distinct chars required; have = currently satisfied. Window is valid iff have == need.
Expand / Shrink
Expand = move R right (window grows). Shrink = move L right (window gets smaller).
At-Most-K trick
Count subarrays with ≤ K of something. Pure sliding-window template; cheap.
Exactly-K trick
exactly(K) = atMost(K) − atMost(K−1). Converts a tricky “exactly K” question into two easy “at most” calls.
Complement window
For some problems (“Take K of each from ends”) you ask “what's the largest middle slice I can keep?” instead of “what's the smallest combined left+right I can remove?”
Bitmask state
For 5 vowels or other small alphabets, encode “which letters have I seen” as a small integer (each bit = one letter). Compare bitmasks instead of maps.

🔎 When Should You Use Sliding Window on Strings?

  • "Longest" / "shortest" substring with a property (≤ K distinct, all vowels, valid budget, …)
  • "Smallest substring containing all of T" (Have/Need)
  • "Count substrings of size K that ..." (Fixed window)
  • "How many anagrams / permutations of P appear in S?" (Fixed window + freq match)
  • "Count substrings with exactly K of X" (At-most-K trick)

📈 The 5 Types of String Sliding Window — Full Breakdown

① Variable Window (Longest / Shortest with Condition)

What it is: Expand R unconditionally. When the constraint breaks, shrink L until it holds. Update the best at each valid step.

Recognize it when:

  • "Longest substring without repeating characters"
  • "Longest substring with at most K distinct"
  • "Longest substring after replacing K chars"

The decision rule:

  • add s[R] to window state
  • while invalid: remove s[L] from state, L++
  • best = max(best, R − L + 1)
Worked Example: Longest Substring Without Repeating — "abcabcbb"
Track last-seen index of each char; L = max(L, lastSeen + 1)
R=0..2
"abc" — all new
best = 3
R=3
'a' seen at 0 → L = 1, window = "bca"
best stays 3
R=4..7
repeats keep pushing L forward
Final best = 3
Code Template: 
int L = 0, best = 0;
<state> window = init;
for (int R = 0; R < s.length(); R++) {
    add s[R] to window;
    while (invalid) { remove s[L]; L++; }
    best = Math.max(best, R - L + 1);
}

② Fixed-Size Window (Size K)

What it is: Window length is fixed at K. Slide one step at a time, updating the metric on add/remove.

Recognize it when:

  • "Max vowels in substring of length K"
  • "K-length substrings with no repeated characters"
  • "All anagrams / permutations of length |p|" (fixed window of size |p|)
  • Repeated DNA substrings of length 10

The decision rule:

  • build first window of size K, capture metric
  • for each slide: metric updates via add s[R], remove s[R−K]
Worked Example: Max Vowels in Substring of Length K
s = "abciiidef", K = 3
Window
"abc" → 1 vowel
best = 1
Slide
"bci" → 1; "cii" → 2; "iii" → 3
best = 3
Code Template: 
int K = ..., cur = 0;
for (int i = 0; i < K; i++) cur += score(s.charAt(i));
int best = cur;
for (int r = K; r < s.length(); r++) {
    cur += score(s.charAt(r)) - score(s.charAt(r - K));
    best = ...;  // max / min / count
}

③ Have / Need (Contains All of T)

What it is: Maintain a need-map (frequencies of t) and a window-map. Two integers, have and need, count how many required characters are currently satisfied. Window valid when have == need.

Recognize it when:

  • "Smallest substring containing all of t"
  • "All substrings that are anagrams of p"
  • Multiplicities matter (need 2 a's, not just 1)

The decision rule:

  • when window[c] reaches need[c]: have++
  • when window[c] drops below need[c]: have--
  • while have == need: try to shrink to find a smaller valid window
Worked Example: Minimum Window Substring — s = "ADOBECODEBANC", t = "ABC"
need = {A:1, B:1, C:1}, needCount = 3
Expand
"ADOBEC" → have == 3 ✓
record length 6
Shrink
drop 'A', have drops to 2 — stop shrinking, resume expanding
More
eventually "BANC" (length 4) — smallest valid window
Answer: "BANC"
Code Template: 
Map<Character, Integer> need = freq(t);
int needCount = need.size(), have = 0;
Map<Character, Integer> window = new HashMap<>();
int L = 0, bestLen = INF, bestL = 0;
for (int R = 0; R < s.length(); R++) {
    window.merge(s.charAt(R), 1, Integer::sum);
    if (need.containsKey(s.charAt(R)) && window.get(s.charAt(R)).equals(need.get(s.charAt(R)))) have++;
    while (have == needCount) {
        if (R - L + 1 < bestLen) { bestLen = R - L + 1; bestL = L; }
        char lc = s.charAt(L);
        window.merge(lc, -1, Integer::sum);
        if (need.containsKey(lc) && window.get(lc) < need.get(lc)) have--;
        L++;
    }
}

④ At-Most-K (and Exactly-K via Subtraction)

What it is: A reusable subroutine: count subarrays with at most K of something. The variable window template applies directly. Counting subarrays ending at each R: add R − L + 1.

For “exactly K” problems, use exactly(K) = atMost(K) − atMost(K−1).

Recognize it when:

  • "Number of substrings with all three characters"
  • "Vowel substrings" (exactly 5 distinct vowels)
  • "Cost within budget" (at-most-budget)
Worked Example: Number of Substrings Containing All Three (a, b, c)
Track last-seen index of a, b, c. For each R, # of valid substrings ending here = min(lastA, lastB, lastC) + 1
Sweep
once all three have been seen, every L ≤ min(last_a, last_b, last_c) works
add min(...) + 1 to total per R
Code Template (At-Most-K Distinct, generic): 
int atMost(String s, int K) {
    Map<Character, Integer> cnt = new HashMap<>();
    int L = 0, total = 0;
    for (int R = 0; R < s.length(); R++) {
        cnt.merge(s.charAt(R), 1, Integer::sum);
        while (cnt.size() > K) {
            char lc = s.charAt(L++);
            cnt.merge(lc, -1, Integer::sum);
            if (cnt.get(lc) == 0) cnt.remove(lc);
        }
        total += R - L + 1;
    }
    return total;
}

⑤ Reframe / Complement / Bitmask

What it is: Some problems aren't obviously sliding-window. The trick is to reframe: maybe ask for the largest middle slice you can keep instead of the smallest piece you remove. Or encode small-alphabet state as a bitmask.

Recognize it when:

  • "Remove from both ends to satisfy X" ↔ "largest middle satisfying complement of X"
  • "All cases of letter present in both cases" — bitmask of (lowercase, uppercase) presence
  • "Balanced string" — largest middle window such that outside counts ≤ n/4
Worked Example: Take K of Each Character from Left and Right

Total of char c = totalc. After taking K of each, the remaining middle must have count[c] ≤ totalc − K for every c. So: find the longest such middle window; answer = n − that length.

// Variable window
int L = 0, best = 0;
for (int R = 0; R < s.length(); R++) {
    add s[R] to window;
    while (invalid) { remove s[L++]; }

// Fixed window of size K
int score = 0;
for (int i = 0; i < K; i++) score += val(s.charAt(i));
int best = score;
for (int r = K; r < s.length(); r++) {
    score += val(s.charAt(r)) - val(s.charAt(r - K));
    best = Math.max(best, score);
}
