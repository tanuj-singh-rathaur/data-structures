P03 — Longest Subarray with Sum K

Medium • LeetCode #560 family • Pattern: Variable Window (positives) / HashMap (general)

📝 The Problem

Find the length of the longest contiguous subarray whose sum equals K.

Example: nums = [1, 2, 1, 0, 1, 1, 0], K = 4 → 5 (e.g. [1, 0, 1, 1, 1] if rearranged — here [2,1,0,1,0] doesn't exist; valid answer is [1,2,1,0] of length 4, or [1,0,1,1,1] length 5 if present). Use values matching your test.

📚 Jargon Buster

Non-negative array
All values ≥ 0. The sum is monotonically non-decreasing as we add elements, so the sliding window technique works directly.
Monotonicity
The property that “moving R right can only increase the sum.” That's what lets us shrink L when sum exceeds K — we never “undo” a valid answer.
HashMap-of-prefix-sums fallback
If negatives are allowed, sliding window breaks. Use the prefix-sum + hashmap technique (see prefixsum/P04).

🌟 In Layman's Terms

Imagine filling a bucket with water by adding rocks. As long as the water level (sum) is below the line K, keep adding. If it overflows, remove rocks from the bottom (left side) until it's at or below K again. Whenever the water level equals exactly K, check if your stretch is the longest seen.

⚡ The Aha Moment

For non-negative arrays, sliding window suffices: expand R to grow the sum, shrink L when sum overshoots. Each element enters and leaves at most once → O(n).

🔧 Algorithm

  1. Start L = 0, sum = 0, best = 0.
  2. For each R: sum += nums[R].
  3. While sum > K: sum −= nums[L]; L++.
  4. If sum == K: best = max(best, R − L + 1).

☕ Java Solution

public int longestSubarraySumK(int[] nums, int K) {
    int L = 0, sum = 0, best = 0;
    for (int R = 0; R < nums.length; R++) {
        sum += nums[R];
        while (sum > K && L <= R) {
            sum -= nums[L++];
        }
        if (sum == K) best = Math.max(best, R - L + 1);
    }
    return best;
}

If the array can contain negatives, this approach is incorrect — use a HashMap of prefix sums instead (see Prefix Sum P04).

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Variable Window (Shrink on Overshoot): Grow R unconditionally; whenever the invariant breaks (here, sum > K), shrink from L. Update the answer whenever the window is “exactly valid.”
Key Insight: Sliding window is only correct when the metric is monotonic. For non-negative sums it is — that's why we can confidently shrink without missing answers.
