P07 — Minimum Window Substring

Hard • LeetCode #76 • Pattern: Have / Need with Frequency Map

📝 The Problem

Given strings s and t, return the shortest substring of s that contains every character of t (counting multiplicities). Return an empty string if no such substring exists.

Example: s = "ADOBECODEBANC", t = "ABC" → "BANC"

📚 Jargon Buster

Need map
Frequency map of t: how many of each character we still owe. Stays constant.
Window map
Frequency map of the current window of s: how many of each char we currently hold.
have / need counters
Two integers. need = number of distinct chars in t (how many independent requirements). have = how many of those requirements are currently fully met. Window is valid when have == need.
Why we use have/need instead of map equality
Comparing two frequency maps every step would be O(26) or O(128). Using two counters makes the validity check O(1).
Multiplicities
If t = "AAB", the window needs two A's, not just one. Frequency maps naturally handle this.

🌟 In Layman's Terms

You have a shopping list (t). You walk down an aisle (s) putting items into a cart. The window is what's currently in the cart. Once your cart contains everything on the list, try removing things from the back — if it's still complete, the smaller cart is better. Keep walking, repeating this expand-then-shrink dance until you've checked everything.

⚡ The Aha Moment

You can detect “cart has everything” in O(1) by maintaining a counter have. Each time the window's count of a required char reaches the needed count, increment have. Window is complete ↔ have == need.

📺 Visual Walkthrough

s="ADOBECODEBANC", t="ABC"  —  need: {A:1,B:1,C:1}, total need=3
Expand
R sweeps right, adding to window map until have==need.
Window grows to "ADOBEC" — A✓, B✓, C✓ → have=3=need length=6, best=6, store window
Shrink
L moves right: A leaves. window map A drops below need → have=2.
Stop shrinking. Resume expanding.
Continue
Eventually find "CODEBA" (have=3 again), then "ODEBAN", then "BANC".
Final: "BANC", length 4 — smallest seen.

🔧 Algorithm

  1. Build need map from t. Compute needCount = need.size() (distinct chars).
  2. Initialize have = 0, L = 0, bestLen = ∞, bestStart = 0.
  3. For each R: add s[R] to window map. If window[c] == need[c], have++.
  4. While have == needCount: record window if smaller. Remove s[L] from window; if window[c] drops below need[c], have−−; L++.
  5. Return s.substring(bestStart, bestStart + bestLen) or "".

☕ Java Solution

public String minWindow(String s, String t) {
    if (t.length() > s.length()) return "";
    Map<Character, Integer> need = new HashMap<>();
    for (char c : t.toCharArray()) need.merge(c, 1, Integer::sum);
    int needCount = need.size(), have = 0;
    Map<Character, Integer> window = new HashMap<>();
    int L = 0, bestLen = Integer.MAX_VALUE, bestStart = 0;
    for (int R = 0; R < s.length(); R++) {
        char c = s.charAt(R);
        window.merge(c, 1, Integer::sum);
        if (need.containsKey(c) && window.get(c).intValue() == need.get(c).intValue()) {
            have++;
        }
        while (have == needCount) {
            if (R - L + 1 < bestLen) { bestLen = R - L + 1; bestStart = L; }
            char lc = s.charAt(L);
            window.merge(lc, -1, Integer::sum);
            if (need.containsKey(lc) && window.get(lc) < need.get(lc)) {
                have--;
            }
            L++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
}

⏳ Complexity

Time
O(|s| + |t|)
Space
O(|alphabet|)

📈 Sliding Window Pattern

Have / Need: The general pattern for “window must contain X” problems. Two counters — need (distinct requirements) and have (currently met) — let you check window validity in O(1).
Key Insight: Don't compare full frequency maps each step. Track only the boundary crossings — when a count reaches the required amount, you've “earned” that requirement. When it dips below, you've “lost” it. Increment/decrement have only at those moments.
