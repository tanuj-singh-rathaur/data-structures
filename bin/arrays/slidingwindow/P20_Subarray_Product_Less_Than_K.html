P20 — Subarray Product Less Than K

Medium • LC #713 • Pattern: Variable Window (positives only)

📝 The Problem

Given nums (positive integers) and integer K, count contiguous subarrays whose product is strictly less than K.

Example: nums = [10, 5, 2, 6], K = 100 → 8

📚 Jargon Buster

Positives only
All values > 0 and product is monotonic on grow/shrink. With zero or negatives the sliding window is invalid.
K ≤ 1 edge case
Since values ≥ 1, every product ≥ 1, so the count is 0.
Why "R − L + 1" per step
When the window [L..R] satisfies product < K, every subarray ending at R and starting at L, L+1, ..., R is also valid. That's R − L + 1 new subarrays.

🌟 In Layman's Terms

Expand R, multiplying the running product. If it crosses K, shrink from L, dividing out. Each step, the number of valid new subarrays ending at R equals the current window length.

⚡ The Aha Moment

Once [L..R] is valid, all sub-windows ending at R are valid too — we count them all in O(1) per R.

🔧 Algorithm

  1. Return 0 if K ≤ 1.
  2. Set L = 0, product = 1, count = 0.
  3. For each R: product *= nums[R]; while product ≥ K, product /= nums[L++].
  4. count += R − L + 1.

☕ Java Solution

public int numSubarrayProductLessThanK(int[] nums, int K) {
    if (K <= 1) return 0;
    int L = 0, count = 0;
    long product = 1;
    for (int R = 0; R < nums.length; R++) {
        product *= nums[R];
        while (product >= K) product /= nums[L++];
        count += R - L + 1;
    }
    return count;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Variable Window (Counting Variant): Same shrink-on-invalid template; the "answer" is built by adding R − L + 1 at every valid R.
Key Insight: The trick of counting R − L + 1 per step is one of the most common subarray-counting patterns — works whenever the property is monotonic in window length.
