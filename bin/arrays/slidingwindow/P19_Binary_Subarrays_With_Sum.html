P19 — Binary Subarrays With Sum

Medium • LC #930 • Pattern: exactly(goal) = atMost(goal) − atMost(goal−1)

📝 The Problem

Given a binary array nums and integer goal, count subarrays summing exactly to goal.

Example: nums = [1,0,1,0,1], goal = 2 → 4

📚 Jargon Buster

Binary array
Only 0s and 1s; sum equals count of 1s.
Goal = 0 edge case
Need to count all-zero subarrays. The atMost(0) − atMost(−1) formula must handle goal − 1 = −1 gracefully; atMost should return 0 for negative inputs.

🌟 In Layman's Terms

Identical machinery to Nice Subarrays (P18): count subarrays with sum ≤ goal, subtract sum ≤ goal−1.

⚡ The Aha Moment

The atMost helper here counts 1s; same template as before. The exactly-K trick handles the “exactly equal” constraint with a single subtraction.

🔧 Algorithm

  1. Helper atMost(nums, S): returns 0 if S < 0; otherwise standard sliding window.
  2. Return atMost(goal) − atMost(goal − 1).

☕ Java Solution

public int numSubarraysWithSum(int[] nums, int goal) {
    return atMost(nums, goal) - atMost(nums, goal - 1);
}
private int atMost(int[] nums, int S) {
    if (S < 0) return 0;
    int L = 0, sum = 0, total = 0;
    for (int R = 0; R < nums.length; R++) {
        sum += nums[R];
        while (sum > S) sum -= nums[L++];
        total += R - L + 1;
    }
    return total;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Sliding Window Pattern

Exactly-K Trick (sum variant): Identical structure to P13 (distinct) and P18 (odd count). Different "what to count," same exactly-K subtraction.
Key Insight: Guarding against S < 0 in atMost is essential. Without it, goal = 0 would call atMost(−1) and crash or return garbage.
