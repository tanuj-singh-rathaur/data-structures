💡 What Is Prefix Sum? (Layman's Explanation)

Imagine you keep a running tally as you walk past a row of jars of coins. After jar 1 you've counted 5 coins. After jar 2, 8 coins. After jar 3, 14 coins. That growing list [5, 8, 14, ...] is the prefix sum.

Now if a friend asks “how many coins are in jars 2 through 3?” you don't recount. You take tally after jar 3 minus tally after jar 1: 14 - 5 = 9. One subtraction. Done.

That's the whole trick: pay O(n) once to build the running totals, and every “sum of a range” question after that takes O(1). It turns a repeated scan into a single subtraction.

📚 Jargon Buster (Confusing Terms Explained)

Prefix
The beginning slice of an array, from index 0 up to some index i. So prefix[3] means “everything from the start up through index 3.”
Prefix sum array
An array where P[i] = sum of all values from index 0 to i-1 (or 0 to i — both styles exist). P[0] is usually 0 (empty prefix).
Range sum / subarray sum
The sum of elements between two indices, e.g. nums[l..r]. With prefix sums it equals P[r+1] - P[l].
Inclusive vs Exclusive
Inclusive means “include both endpoints.” Exclusive means “stop just before.” Prefix-sum formulas usually use exclusive upper-bound indices.
O(1) query
A “constant time” answer — doesn't matter if the range is 2 elements or 2 million, the lookup takes the same tiny amount of time.
HashMap of prefix sums
A dictionary mapping “a prefix sum value I've seen” to “how many times / at which index.” Used when you want to find subarrays matching a target without re-scanning.
Subarray
A contiguous slice of the array (elements next to each other). Different from a “subsequence,” which can skip elements.
XOR prefix
Same idea as prefix sum but with XOR instead of addition. Works because XOR is its own inverse: a ^ a = 0.
Difference array
The opposite of prefix sum: store the change at each step instead of the total. Range-update problems use this and then take a prefix sum at the end.

🔎 When Should You Use Prefix Sum?

  • You're asked the sum of a range multiple times.
  • You're searching for a subarray with a target sum (or count, or XOR).
  • The array is not changing — immutable queries are the sweet spot.
  • Brute force is O(n·q) for q queries, and you want O(n + q).
  • You need a pivot / balance point where left sum equals right sum.
  • You see addition or XOR being repeated over windows.

📈 The 4 Types of Prefix Sum — Full Breakdown

① Range-Sum Query (Immutable)

What it is: Build a prefix array once. Answer any “sum from index l to r” question with one subtraction.

Recognize it when:

  • You'll answer many range-sum queries on a fixed array
  • The brute approach would loop l..r per query

The formula:

  • Build P[i+1] = P[i] + nums[i] with P[0] = 0
  • Range sum nums[l..r] = P[r+1] - P[l]
Worked Example: Sum of indices 1..3 of [3, 5, 2, 7, 1]

Code Template: 
int[] P = new int[n + 1];
for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];
// Query l..r in O(1):
int rangeSum = P[r + 1] - P[l];

② Pivot / Balance Index

What it is: Find an index where the sum to the left equals the sum to the right. The total stays fixed, so you just walk left-to-right and check.

Recognize it when:

  • Looking for an index where two halves “balance”
  • You need to check every index efficiently

The trick:

  • Total = sum of all elements
  • At index i: rightSum = total − leftSum − nums[i]
  • Found when leftSum == rightSum. Then add nums[i] to leftSum and move on.
Worked Example: Find pivot in [1, 7, 3, 6, 5, 6]

i=3

Code Template: 
int total = 0; for (int x : nums) total += x;
int leftSum = 0;
for (int i = 0; i < n; i++) {
    if (leftSum == total - leftSum - nums[i]) return i;
    leftSum += nums[i];
}
return -1;

③ HashMap of Prefix Sums (Count / Find Subarray)

What it is: Walk once, keep a running prefix sum, and store “how many times I've seen this sum.” When the current sum minus the target was seen before, those previous positions are the left edges of valid subarrays.

Recognize it when:

  • Counting subarrays whose sum / XOR equals K
  • You can't sort or use a sliding window (negatives present, or XOR)
  • Brute force is O(n²)

The key identity:

  • subarraySum(i..j) = P[j+1] − P[i]
  • If we want subarraySum == K then P[i] = P[j+1] − K
  • So at each j we ask: “how many earlier prefixes equal currentPrefix − K?”
Worked Example: Count subarrays with sum = 3 in [1, 2, 3, −1]
Map starts {0:1} (empty prefix has been “seen” once)
i=0
prefix=1, need 1−3=−2 — not in map
map = {0:1, 1:1}, count=0
i=1
prefix=3, need 3−3=0 → map has 0 (count 1)
count += 1 → 1 (subarray [1,2]) map = {0:1, 1:1, 3:1}
i=2
prefix=6, need 6−3=3 → map has 3 (count 1)
count += 1 → 2 (subarray [3]) map = {0:1, 1:1, 3:1, 6:1}
i=3
prefix=5, need 5−3=2 — not in map
count stays at 2 Final answer: 2
Code Template: 
Map<Integer,Integer> seen = new HashMap<>();
seen.put(0, 1);                  // empty prefix
int prefix = 0, count = 0;
for (int x : nums) {
    prefix += x;
    count += seen.getOrDefault(prefix - K, 0);
    seen.merge(prefix, 1, Integer::sum);
}
return count;

④ Prefix + Suffix (Two-Pass Product / Sum)

What it is: For each index, you need “everything to the left” combined with “everything to the right.” Sweep left-to-right to compute the prefix, then right-to-left to multiply in the suffix.

Recognize it when:

  • Compute an answer at every index using both sides
  • “Without using the current element” and “without division” are explicit constraints
  • You'd otherwise need O(n²) (recompute neighbors for each index)

The trick:

  • Pass 1: result[i] = product of everything before i
  • Pass 2: walk right-to-left, keep a running “suffix product,” multiply it into result[i]
Worked Example: Product Except Self for [1, 2, 3, 4]
Two sweeps — left then right

Code Template: 
int[] res = new int[n];
res[0] = 1;
for (int i = 1; i < n; i++) res[i] = res[i-1] * nums[i-1];
int suffix = 1;
for (int i = n - 1; i >= 0; i--) {
    res[i] *= suffix;
    suffix *= nums[i];
}

// Build prefix sums (1-indexed style, easiest for range queries)
int[] P = new int[n + 1];
for (int i = 0; i < n; i++) P[i + 1] = P[i] + nums[i];

// O(1) range query: sum of nums[l..r]

// HashMap variant — count subarrays where sum == K
Map<Integer,Integer> seen = new HashMap<>();
seen.put(0, 1);
int prefix = 0, count = 0;
for (int x : nums) {
    prefix += x;
    count += seen.getOrDefault(prefix - K, 0);
    seen.merge(prefix, 1, Integer::sum);
}
