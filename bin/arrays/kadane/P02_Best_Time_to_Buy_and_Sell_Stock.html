P02 — Best Time to Buy and Sell Stock

Easy • LeetCode #121 • Pattern: Min-So-Far / Implicit Difference Kadane

📝 The Problem

You're given prices[i] = the stock price on day i. Buy on one day, sell on a later day. Return the max profit (0 if none possible).

Example: prices = [7, 1, 5, 3, 6, 4] → 5 (buy day 1 at 1, sell day 4 at 6)

📚 Jargon Buster

Buy and sell once
You pick one buy day and one strictly later sell day. No short-selling, no holding multiple positions.
Profit
price[sell] − price[buy]. Negative means loss; we'd just not trade, so floor is 0.
minSoFar
The lowest price encountered up to and including the current day. The buy day — we'd always buy at the cheapest moment we've seen.
Why this is Kadane in disguise
Profit equals the sum of consecutive day-to-day differences diff[i] = price[i]−price[i−1] over some range. Max profit = max subarray sum of diff. We just don't bother computing diff explicitly.

🌟 In Layman's Terms

Walk through the prices day by day. Always remember the cheapest day you've seen so far — that's your candidate buy day. Each new day, ask: “if I sold today at this price, what's my profit compared to my cheapest buy day?” Keep the best.

⚡ The Aha Moment

You never need to consider buying on a day that isn't the cheapest so far — any earlier cheaper day would have produced more profit. So you only need one variable for the buy side: the running minimum.

🔧 Algorithm

  1. Initialize minPrice = ∞, best = 0.
  2. For each p in prices: update minPrice = min(minPrice, p), then best = max(best, p − minPrice).
  3. Return best.

☕ Java Solution

public int maxProfit(int[] prices) {
    int minPrice = Integer.MAX_VALUE, best = 0;
    for (int p : prices) {
        minPrice = Math.min(minPrice, p);
        best = Math.max(best, p - minPrice);
    }
    return best;
}

⏳ Complexity

Time
O(n)
Space
O(1)

📈 Kadane Pattern

Implicit Difference Kadane: Equivalent to running Kadane on the daily-difference array, but compressed: minSoFar implicitly tracks where the “current run” would have started.
Key Insight: When the problem has “pick i < j to maximize f(j) − g(i),” you almost always only need to track one running extreme of g(i). That collapses the search from O(n²) to O(n).
