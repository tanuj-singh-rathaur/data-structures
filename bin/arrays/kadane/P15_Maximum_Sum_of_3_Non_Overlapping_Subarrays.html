P15 — Maximum Sum of 3 Non-Overlapping Subarrays

Hard • LC #689 • Pattern: Fix Middle; Prefix-Best + Suffix-Best

📝 The Problem

Find three non-overlapping subarrays of length K with maximum total sum. Return the lexicographically smallest list of their start indices.

Example: nums = [1,2,1,2,6,7,5,1], K = 2 → [0, 3, 5]

📚 Jargon Buster

K-sum array
For each i, sum of nums[i..i+K−1]. Compute in O(n) via sliding window.
left[i]
Index of the best K-window starting in [0..i]. Build by sweeping left-to-right tracking the running max (strictly greater — ties favor leftmost).
right[i]
Index of the best K-window starting in [i..n−K]. Build by sweeping right-to-left (≥ for ties — favor leftmost when equal).
Fix middle
For every possible middle window start j (in [K..n−2K]), combine left[j−K] + j + right[j+K].

🌟 In Layman's Terms

For each possible middle window, look up the best K-window to the left and the best K-window to the right (both pre-computed). Combine; track the maximum.

⚡ The Aha Moment

Three free choices look daunting, but fixing the middle constrains both sides cleanly. Pre-computed prefix-best and suffix-best arrays do all the heavy lifting.

🔧 Algorithm

  1. Compute sum[i] for K-window starts.
  2. Build left[i]: best start index in [0..i].
  3. Build right[i]: best start index in [i..end].
  4. For each middle start j in [K, n−2K]: candidate = sum[left[j−K]] + sum[j] + sum[right[j+K]]; track winner.

☕ Java Solution

public int[] maxSumOfThreeSubarrays(int[] nums, int K) {
    int n = nums.length, m = n - K + 1;
    int[] sum = new int[m];
    long s = 0;
    for (int i = 0; i < K; i++) s += nums[i];
    sum[0] = (int) s;
    for (int i = 1; i < m; i++) sum[i] = sum[i - 1] + nums[i + K - 1] - nums[i - 1];

    int[] left = new int[m];
    int best = 0;
    for (int i = 0; i < m; i++) {
        if (sum[i] > sum[best]) best = i;
        left[i] = best;
    }
    int[] right = new int[m];
    best = m - 1;
    for (int i = m - 1; i >= 0; i--) {
        if (sum[i] >= sum[best]) best = i;
        right[i] = best;
    }
    int[] ans = new int[]{-1, -1, -1};
    int bestTotal = -1;
    for (int j = K; j <= m - 1 - K; j++) {
        int l = left[j - K], r = right[j + K];
        int total = sum[l] + sum[j] + sum[r];
        if (total > bestTotal) { bestTotal = total; ans = new int[]{l, j, r}; }
    }
    return ans;
}

⏳ Complexity

Time
O(n)
Space
O(n)

📈 Kadane Pattern

Prefix-Best + Suffix-Best: Pre-compute the best-so-far from both directions. Then a single sweep through possible middles combines them in O(1).
Key Insight: “Best left” uses strict > (favor earliest tie). “Best right” uses ≥ (also favor earliest, since right sweeps from end). These tie-break rules guarantee the lex-smallest answer.
